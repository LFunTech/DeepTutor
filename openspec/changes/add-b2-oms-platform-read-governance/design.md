# 设计：EduPlus2 平台身份、动作权限与 OMS 治理边界

平台主体必须由 EduPlus2 受信 OIDC issuer/JWKS、**专用 OMS audience/client**、可信签名、有效期与权限权威产生，并把平台 `sub` 绑定受控内部主体；平台与租户路径可以共用 Keycloak realm issuer，但不能由客户端 `X-Scopes`、JWT realm/client role、用户名、现有要求 `tid/eui/sub/azp` 的租户换票或 `tenant_admin` 身份推导。`tid/eui/eit` 在 EduPlus2 文档中可空，不能用它们推断平台权限。权限应从 EduPlus2 权限 API/OpenFGA 逐动作查询，所需 OMS relation/object/目标 tenant 范围、权限/撤权版本和 operator 可调用端点须由发送端契约锁定；通用权限 API 文档注明租户 admin 前置，不能未经确认复用于平台 operator。`require_platform_permission(action)` 每动作执行，先认证/授权再解析显式目标 tenant 与可操作范围。跨租户数据使用受限受审计事务，不能把 BYPASSRLS 连接交普通请求；无权 403、未认证 401、目标不存在按防枚举策略 404。平台与租户 session 不互继承。

API 草案：`GET /api/v1/oms/summary|tenants|tenants/{id}|resources|providers/status|supply|entitlements|quotas|usage|reconciliation|cost|audit|jobs`，以及与 `add-enterprise-oms-business-logic` 总账和配置 change 对应的受控写动作；不在此 change 建第二套供给/用量权威。租户详情仅展示 EduPlus2 lifecycle/本地隔离、同步异常和**逐服务**授权/额度状态，不再有独立欠费模型资格。列表分页、范围有上限；普通运营 DTO 只含必要脱敏元数据，成本需 `ops.cost.read` 独立授权，Secret 明文、私有正文、完整 JWT/token/长期下载 URL 一律不返。TMS 仅从安全投影读取当前租户配额/用量，不能调用 OMS 专有 DTO。ObjectStore summary 不可冒充实际供应商用量。

能力矩阵：`ops.oms.access` 控入口；`ops.tenants.read`、`ops.clients.read`、`ops.providers.read/manage`、`ops.credentials.manage`、`ops.supply.read/manage`、`ops.entitlements.read/manage`、`ops.quotas.read/manage`、`ops.usage.read`、`ops.reconciliation.manage`、`ops.cost.read`、`ops.audit.read/export`、`ops.jobs.read` 按动作分离。平台 admin/operator/auditor 的默认权限由 EduPlus2 版本化模板给出，自定义角色须显式授权；DeepTutor 判断权限 key，不以角色名称自动授权。OMS 仍无租户开停、client 注册、成员管理写能力。配置、供给、授予、核对、导出均需 reason、expected_version/幂等键及 actor/目标/前后版本/request ID/结果的审计；Secret/成本权限不从普通读权限继承。所有 backend-managed status 返回稳定 `code`、`label`/`tone`、`description`、`observed_at` 与来源；详情含 `impact`、`next_action`、时效和 descriptor 版本/语言。企业 PG 仅迁移平台主体绑定、权限快照/版本和审计索引；EduPlus2 若新建 role/relation/scope/client，必须在发送端走受控迁移。菜单、路由、按钮和 API 同 key 验证。核心旧 OMS router 不挂入企业 app，不能靠注册顺序覆盖；CLI/SDK/后台不设直写旁路。验收先有合成错 issuer/audience/签名/撤权、tenant admin/伪造 header、跨租户/Secret/成本/导出负例，再开放写入口。
