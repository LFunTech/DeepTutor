## Purpose

定义云端 OMS 在正式运营时对 DeepTutor 平台资源、供应商服务供给、租户服务授权与配额、真实调用消耗及治理数据的业务规则；明确它与 EduPlus2、TMS、本地 DeepTutor 产品之间的权威和安全边界。

## ADDED Requirements

### Requirement: OMS 必须是云端平台管理权威且不得破坏本地设置

企业云端 SHALL 只通过获授权 OMS 管理平台级配置、资源目录、服务供给、租户服务授权与配额；企业装配 MUST 阻断 DeepTutor 原平台管理页、管理 API、CLI/SDK 等可绕过的写入路径，而非只隐藏菜单。DeepTutor 本地部署 SHALL 保留本地 Web 设置能力和原有运行语义。OMS/TMS 独立前端与共用组件的展示行为不得转移后端权威。

#### Scenario: 云端用户直连旧设置接口
- **WHEN** 云端用户绕过 OMS 直调旧 DeepTutor 平台设置写接口
- **THEN** 企业入口拒绝或不装配该接口，不能凭租户管理员身份改平台设置
- **AND** 本地部署仍可按本地产品原有权限维护相应设置

### Requirement: 平台资源目录必须按 DeepTutor 对象与作用域分类

OMS SHALL 覆盖模型/外部服务、Agent/Capability、工具/Skill/MCP/集成、知识与内容基础能力、运行资源。每个目录项 MUST 标明平台、租户或个人作用域，区分可调用服务与不可直接计量的模板/策略；只有确认了执行边界和单位的可调用服务才能建立执行配额。OMS MUST NOT 因运营角色读取个人会话、记忆、笔记或文件正文。

#### Scenario: 查看 Agent 与 OCR 相关资源
- **WHEN** 平台人员查看 Agent、文档解析/OCR 与个人学习资源
- **THEN** OMS 可呈现平台模板、依赖服务和脱敏运行状态，但不会把 Agent 子调用重复当独立服务消耗，也不会读取个人正文
- **AND** OCR 仅按 DeepTutor 真实解析能力呈现，不凭目录项虚构独立 OCR Provider

### Requirement: OMS 必须按租户授权 global Skill 并保留 tenant 同名优先

OMS SHALL 将云端 Skill 的 owner 与来源分开：owner 仅为 `global` 或指定 `tenant`；OMS 仅创建、受控导入、审核发布与按目标租户授权 `global` Skill，TMS 维护其自身 tenant owner Skill。仅已发布且已授权目标租户的 global Skill 能进入该租户可用清单；授权生效无需 TMS 再向成员/应用分配。给已有同名 tenant Skill 的租户补授权 global Skill 时，OMS SHALL 显示 tenant 版本仍优先，不得覆盖租户内容或错误宣称 global 为运行时当前版本。Skill 自身不作为独立 Token 配额服务；当前 DeepTutor 用户级 Skill API 不得冒充云端 owner/授权 API。

非 builtin global Skill 的创建与更新 MUST 提交包含唯一有效 `SKILL.md` 的完整 ZIP 包；受控 Hub 导入 MUST 先取得并校验真实包。服务端 MUST 从 `SKILL.md` 的 YAML frontmatter 与 Markdown 正文读取全部 Skill 内容元数据与说明，拒绝缺失或无效 `name`/`description`、空正文、目录名不一致及危险/损坏/超限 ZIP，不得以表单字段、ZIP 文件名或请求自报 owner/状态补齐。owner、来源、审核/发布状态、授权和包摘要 MUST 从可信平台上下文与不可变包版本确定；脚本及 `always` 未经安全审查不得执行或启用。更新 MUST 形成待复核的新包版本，不得在线覆写已发布内容或借旧授权静默生效。

#### Scenario: 后授权同名 global Skill
- **WHEN** 平台管理员把已发布的 global Skill 授权给已有同名 tenant Skill 的学校
- **THEN** OMS 说明该校运行时仍优先使用 tenant 版本，global 版本保留为已授权但被覆盖；其他没有同名 tenant Skill 的获授权租户可直接使用 global 版本

### Requirement: 云端 builtin Skill 必须默认未授权且在所有执行入口受控

DeepTutor 随程序打包的 builtin Skill SHALL 在云端映射为 `owner=global, source=builtin` 的只读目录条目；OMS 不得在线编辑、删除或复制包内内容来伪装普通 global Skill。企业首次启用及后续新增 builtin MUST 默认没有任何租户授权，只有 OMS 针对经复核的打包版本显式授权给目标租户后才能对该租户可见/可用。授权 SHALL 与 `requires` 运行条件分别校验；依赖缺失不可用。企业运行时 MUST 在 Skill manifest、显式请求、`read_skill` 正文与参考文件、`always` 自动注入及受影响的 HTTP/WS、CLI、SDK、Partners 入口执行同一 owner/租户授权过滤；不得依赖 TMS 前端隐藏或用户级 `/api/skills` 的既有可见性。打包版本或内容摘要变化 MUST 记录并经平台复核后才改变已授权租户实际读取的内容，不能沿旧授权静默生效。DeepTutor 本地部署现有 builtin 自动发现及本地用户覆盖规则 SHALL 保持不变；若扩展层缺少必要拦截点，核心通用 seam 须先严格审阅。

#### Scenario: 云端新租户未获 builtin 授权
- **WHEN** 新租户发起请求并显式指定 `pdf`，或试图通过 `read_skill` 读取其正文/参考文件，而 OMS 尚未授权该 builtin
- **THEN** 企业执行路径拒绝或报告 Skill 不可用，且其 manifest/`always` 注入不包含该 Skill；本地 DeepTutor 的 `pdf` 可见性不受影响

#### Scenario: 已授权 builtin 缺少运行依赖
- **WHEN** 租户已获 `pdf` builtin 授权，但执行环境缺少该 Skill 所需的 shell sandbox
- **THEN** 目录可显示“已授权·暂不可用”和缺失条件，运行时不绕过 `requires` 使用该 Skill

#### Scenario: 升级改变 builtin 包内容
- **WHEN** 程序升级将同名 builtin 的 `SKILL.md` 内容改为新摘要
- **THEN** OMS 留下版本差异和影响租户记录；未经复核，旧授权不得让新内容静默进入这些租户的运行上下文

### Requirement: 全服务配置必须继承 DeepTutor 现有条件语义并由执行者确认

OMS SHALL 管理 DeepTutor 已支持的连接、LLM、task、embedding、search、TTS、STT、imagegen、videogen，以及文档解析/RAG、视频学习和具有平台设置的外部 Agent/工具。可编辑属性、候选值、默认值、条件显示和校验 MUST 来自相应真实 descriptor/执行契约；不得以统一 LLM 表单或仅前端硬编码替代。平台配置 SHALL 区分草稿、测试、待生效、已生效、失败与回退；发布版本必须由发布时目标执行者集合逐一确认，部分确认或超时不得整体显示已生效，新执行者也须在接受流量前装载已生效版本。保存或复制 desired 值不能证明已生效，Secret 明文不得进入列表、响应、审计或日志。

#### Scenario: 发布搜索与任务模型设置
- **WHEN** 管理员分别发布搜索服务与未单独配置的 task 服务
- **THEN** 搜索配置不被要求选择虚构模型，task 的 LLM 回退来源被清楚保留
- **AND** 只有相应真实执行者确认所选版本后才显示已生效；失败时保留已确认的上一 active 版本

#### Scenario: 多执行者部分确认
- **WHEN** 一次配置发布面向多个执行者，而其中一个实例超时或确认了错误版本
- **THEN** 该发布不能整体标为已生效，未确认实例不得以新版本接收流量，上一已确认版本保持可用或进入受控回退

### Requirement: 服务供给必须有可验证来源、适用范围和单位

OMS SHALL 按供应商资源方案和补充记录保存服务、provider/model 或兼容池、原生单位、数量或可验证上界、有效期、来源凭据引用及状态。每个有限供给批次 MUST 分开保留终身上界、历史实际消耗与当前可授予量；当前可授予量只考虑仍有效的兼容批次，并扣除未使用承诺及在途预留，不得因批次过期抹去历史消耗。不同单位、供应商适用范围或有效期不可互换时不得合并。金额余额、credits、pay-as-you-go 或合同描述若没有可核验的执行单位和硬上界 MUST 标为不可精确授予或待核对，不得凭任意汇率生成硬额度；在未建立经批准的有界供给契约前，不得为该服务发放硬配额或放行依赖硬配额的新调用。

#### Scenario: 采购记录只有金额余额
- **WHEN** 供应商仅提供金额或 credits，不能将其与 DeepTutor 调用单位可靠对应
- **THEN** OMS 展示来源和待核对状态，但不把金额直接换成可授予的 Token/次数

#### Scenario: 供给批次过期
- **WHEN** 某批次过期而仍有历史消耗及未使用承诺
- **THEN** 历史消耗继续关联该批次且不计入当前有效供给，未使用承诺不能用于新调用；尚未确认的在途调用保持预留和待核对，不通过抹账释放

### Requirement: 租户服务授权和配额配置只能由 OMS 写入

OMS SHALL 对可信目标租户按服务配置访问授权，并在**同一配额列表**记录获取方式为赠送或充值的额度授予、调整、撤销、单位、来源、有效期与操作者。授予前 MUST 验证对应授权、兼容的有效供给、可授予量及状态版本，并记录该授予在一个或多个供给批次中的承诺分配；授予有效期不得晚于支撑它的供给有效期，除非已有另一个可验证批次完成受控重绑定。授予只形成未使用承诺，不是实际消费。TMS SHALL 只读取当前租户的配额投影和消耗明细，不得创建、调整、撤销、充值、赠送或设置成员/应用配额上限；应用/成员的服务访问 grant 不等于额度分配。

#### Scenario: 运营人员向租户授予赠送与充值额度
- **WHEN** 获授权平台人员为同一服务授予一笔赠送和一笔充值额度
- **THEN** 两笔记录进入同一列表并保留各自来源、单位、有效期和操作审计，兼容供给的可再授予量相应减少
- **AND** TMS 可看本租户记录及余额，但没有额度写入动作或接口

#### Scenario: 并发授予超过可用供给
- **WHEN** 两个并发授予请求合计超过同一兼容供给的可授予量
- **THEN** 至多一个或部分受控请求成功，系统不得形成超额承诺或仅凭页面余额通过

### Requirement: 配额消耗必须赠送优先且不得双扣

每个可计费供应商调用尝试 SHALL 先消耗有效赠送额度，再消耗有效充值额度；同类额度按明确且稳定的有效期及授予顺序处理，一次尝试可拆分到多笔额度，供应商供给对该尝试只结算一次。逻辑 `operation_id` 可以包含多个可计费 `attempt_id`；每次实际发往供应商的重试均须有独立预留和结算，重复到达的同一 attempt 结果不得双扣。已结算历史不得因后续赠送、调整、过期或撤销而追溯重分摊。过期/撤销只能释放尚未消耗且未被不确定尝试占用的承诺。

#### Scenario: 一次供应商尝试跨赠送与充值额度
- **WHEN** 单次可信供应商尝试的用量超过剩余赠送额度而不超过赠送与充值额度之和
- **THEN** 该 attempt 先关联赠送剩余量，再关联充值部分，供给侧对该 attempt 只记录一次真实消耗

#### Scenario: 重试与迟到响应
- **WHEN** 一个逻辑 operation 两次请求均到达供应商且均产生可信消耗，第一条 attempt 的结算事件重复到达，第二条在赠送额度追加后才被核对
- **THEN** 两个可计费 attempt 分别消耗并汇总至同一 operation，重复的第一条结果不再扣量，旧尝试不重分摊给新授予

### Requirement: 可调用服务必须在真实执行边界做准入与可信计量

DeepTutor 的企业执行路径 SHALL 在实际服务调用前按可信租户、调用主体类型、适用的用户/应用或服务身份、服务授权、配置 readiness、兼容供给和可用配额做准入；CLI、HTTP/WS、SDK、后台与 Agent 子调用不得有旁路。每项正式开放的可调用服务 MUST 有可信单位、上界预留和待核对策略；无兼容供给硬上界或无法保守预留时拒绝新调用，不默认无限放行。Token 型调用已核对量 MUST 来自供应商真实 usage 或可核验对账；非 Token 服务保留其原生单位，只有执行边界能可靠计数时才可用调用次数。复合 Agent 与子服务不得对同一用量重复扣减。

#### Scenario: 流式模型调用未返回最终 usage
- **WHEN** 服务调用已经发出但最终 usage 未返回且供应商消耗无法确认
- **THEN** 调用和相关预留标记待核对，不能把消耗记零、释放预留或宣称精确余额

#### Scenario: Agent 调用模型与搜索
- **WHEN** 一个 Agent 流程实际调用 LLM 与搜索服务
- **THEN** 两项底层服务各按其可信单位结算一次；Agent 顶层可记录流程状态，但不得再扣相同底层用量

#### Scenario: 后台调用缺少服务身份授权
- **WHEN** 后台任务只有 tenant ID 而没有可信发起者/服务主体及适用授权
- **THEN** 对外服务调用被拒绝，不能借缺少 app ID 绕过应用或服务身份准入

### Requirement: 配额或供给不足只能限制受影响服务的新调用

某租户的服务额度耗尽 SHALL 拒绝该租户该服务的新调用；平台兼容供给不足 SHALL 以不同原因拒绝受影响的服务调用。两种情况均不得改写 EduPlus2 租户生命周期、注销会话或阻断登录、OMS/TMS 管理、历史查询及其他仍可用服务。流式/异步服务无法作上界预留时不得宣称严格硬配额，并且不得放行其新调用；已发出的不确定结果持续待核对。

#### Scenario: OCR 额度耗尽而 LLM 仍有额度
- **WHEN** 某租户 OCR 配额耗尽、LLM 配额仍可用且租户生命周期正常
- **THEN** 新 OCR 调用被拒绝并标注租户额度不足，LLM、登录、管理和历史查询仍可用

### Requirement: 用量与供给对账必须保留可追溯事实

每条结算或待核对记录 SHALL 关联可信 tenant、调用主体类型及其身份、适用时的 user/app ID、服务、provider/model、供给批次与授予分摊、`operation_id`、唯一 `attempt_id`、可取得时的供应商请求 ID、时间、原生单位、usage 来源与核对状态。重试、取消、超时和异步任务 MUST 区分未发出、已发出未知结果和可信完成；未知远端消耗不能按失败零耗处理。OMS SHALL 能按租户→服务→用户/应用/服务主体→单次尝试追溯并以权限受控的人工核对/更正流程保留原始事实和调整审计，而非原地覆盖。

#### Scenario: 远端超时后对账确认已消耗
- **WHEN** 调用超时先进入待核对，供应商对账后来确认实际用量
- **THEN** 原调用转为已核对并产生可追溯结算/调整，不新增第二次独立消费，不抹掉先前待核对记录

### Requirement: 供应商成本只能在 OMS 内按可信证据归集

OMS SHALL 将供应商采购金额/币种或版本化成本条件视为内部供给元数据，仅向获专门成本权限的平台主体展示。按租户、服务或调用拆分供应商成本时，MUST 有对应真实供应商调用、适用单价/分摊契约及单位证据；资料不足 SHALL 显示未核定，不能估算为零。供应商成本不等于租户售价，本目标 MUST NOT 产生租户费用、账单、每百万 Token 价格、欠费状态或支付入口。

#### Scenario: 只有 Token 用量而没有供应商成本条件
- **WHEN** 某调用有可信 Token 用量但采购合同未给出可用于该调用的成本规则
- **THEN** OMS 可展示用量及未核定成本，不展示虚构的零成本或租户应付费用

### Requirement: 租户生命周期只能由 EduPlus2 权威驱动

OMS SHALL 只读展示 EduPlus2 签名事件形成的租户外部资格、本地隔离/初始化状态及同步异常；不得提供租户开通、暂停、恢复写动作。额度耗尽不得生成 `tenant.suspended` 或旧欠费模型资格事件。生命周期事件自身的签名、版本、重放与对账由其独立实施契约负责，OMS 不建立第二份状态权威。

#### Scenario: 平台人员尝试停用租户
- **WHEN** 平台人员尝试从 OMS 停用租户或把额度不足当作租户停用
- **THEN** OMS 不提供该动作，服务端拒绝对应写入；租户状态仍由 EduPlus2 事件及独立本地隔离来源决定

### Requirement: OMS 动作权限、审计和数据投影必须贯穿后端

OMS SHALL 按 **EduPlus2 独立平台身份与权限**、动作能力、显式目标租户及数据范围鉴权；该平台主体不得由现有租户用户换票、`tenant_admin` 身份或客户端 header/任意 claim 推导，发送端 issuer/audience、权限/撤权版本与默认/自定义角色须有受控契约和迁移。平台配置、Secret、供给采购、租户授权/配额、用量核对、成本、审计与导出须分别授权。`tenant_admin`、普通用户、auditor 或仅有只读权限的 operator 不得通过直接 API、导出、旧管理入口、共享组件或伪造 header 扩权。配置/授予/采购/核对写入 SHALL 记录操作者、对象、版本、原因、结果和关联 ID；状态展示 SHALL 区分待生效、待核对、供给不足、租户额度不足、同步延迟与无权限。发送端契约和合成负例通过前，跨租户写 router MUST NOT 装配。

#### Scenario: 租户管理员直调 OMS 配额接口
- **WHEN** 租户管理员伪造目标 tenant 或平台角色调用 OMS 授予接口
- **THEN** 后端拒绝且不泄露其他租户是否存在，审计安全事件

#### Scenario: 无成本权限的运营人员查询用量
- **WHEN** 有用量读取权但没有成本读取权的运营人员打开调用详情或导出
- **THEN** 后端返回可信用量和非敏感状态，不返回供应商采购金额、成本拆分、Secret 或私有正文
