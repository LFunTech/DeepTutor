# 第三方 Capacity 开发规范文档设计

## Context

见 [proposal.md](proposal.md)。目前文档站只针对企业第三方调用方，且企业 `start_turn` 仅开放 `chat` 顶层能力：`skills`、`knowledge_bases` 是受权资源选择，非空 `mcp_tools` 不能作为可执行能力依赖。DeepTutor 本地／上游实现另有多类扩展协议；相关 OMS/TMS 资源管理提案不能当作已上线能力。公开站点的现有契约测试禁止内部路径、内部实现和演示页面内容出现在 MDX。

## Goals / Non-Goals

- 让开发者按交付物选择正确扩展类型，并能据每类的输入输出、安全约束和检查项开发、测试。
- 通过显著的“适用状态”区分当前企业正式调用契约、本地／自部署开发参考、尚未开放的企业扩展安装或执行；示例绝不暗示后者已可用。
- 不增加安装／发布／审核流程、接口承诺、运行时功能或运营管理说明；不讲内部装配、持久化、权限实现或执行基础设施。

## Decisions

### 1. 一类一页，以扩展产物而非管理入口组织

在 `docs-site/docs/agent-developer/capacities/` 增加目录页及九页；侧边栏单设“Capacity 开发规范”，与已有 API 目录并列。目录页用决策表区分：MCP server、单次 Tool、SKILL.md、知识资源、自定义顶层能力、chat 循环扩展、可视化渲染器、阅读动作、CLI 应用。知识库是可被引用的内容资源而非代码插件；CLI 应用与阅读／可视化扩展是相邻扩展，不把它们冒充 `start_turn.capability`。Partner／channel、模型 provider、会话附件只在目录页界定为非本目录对象，不加虚假的 Capacity 页面。

替代方案是按 OMS/TMS 上传位置组织，但这会提前承诺尚未交付的发布路径，也不帮助开发者选择协议。

### 2. 每页以已实现的完整契约为主体，示例为辅

固定顺序：用途和适用状态、当前已实现交付物、**字段/方法及校验表**、生命周期与输入输出、安全／资源边界、错误/限制、可验证示例、自测清单、相关正式 API 链接。对 Python 扩展写清已实现的类/入口点/方法契约，对数据类写清当前可接受的格式和边界；不是当前产品契约的示例元数据必须删除或显式改为建议。MCP 标准与 DeepTutor 当前适配子集分开描述。代码中未实现的校验、配置或发布能力不得写成现状。

替代方案是全用单一概览；无法满足“每类独立详细页”，也难以对各类型分别给出验证标准。

### 3. 把当前可用性作为文档不变量

目录页和每页明确：开发规范 ≠ 企业扩展上线；当前企业可用的是已文档化的 HTTP／WS 调用、受权 Skill/KB ID 的请求选择；非空 MCP、自定义顶层能力及其他开发者扩展不应被写成已可经企业接口安装／执行。是否能在自部署版本启用，取决于该版本和部署方配置；不把本地路由当企业契约。与现有 `capability-selection.mdx`、`start_turn.mdx` 交叉链接而不复制可变的 API 字段表。

替代方案是给所有类型都写调用演练；它会制造第三方无法兑现的承诺。

### 4. 内容事实来源与安全审稿

以**当前代码和相关测试**中的公开协议/格式约束、现有第三方 API 页面为依据。技术源检查包括 Tool/Capability/LoopExtension 协议、Skill 元数据与包限制、知识库命名/文件/状态、MCP 当前可消费的结果类型、Visualizer 包与渲染消息、Reading 扩展输入/输出限制、CLI 应用目录/执行协议；提案仅用于判定未来边界，不作为当前可用事实。MDX 可公开开发者必须实现的接口名与限制，不出现源码路径、内部装配、数据库/队列/租约/部署细节、管理端权限实现、未发布 URL。校验除结构外还应核对文档列出的关键数值/枚举与代码一致；保留现有全站私有内容扫描。

替代方案是仅靠人工审阅，但内容数量较多且当前状态容易被后续编辑误改。

## Risks / Trade-offs

- [扩展协议与企业开放状态被混淆] → 页面顶部统一标注适用状态；目录用“规范／正式调用”双轴说明；契约测试覆盖关键语句。
- [自部署协议以后变化] → 写全当前代码可核实的字段与限制，标明适用版本/环境，并用契约测试检测关键漂移；不承诺跨版本二进制兼容。
- [示例泄露内部实现或暗示可安装] → 示例限定为交付物片段／接口形状，不含管理 URL；沿用 MDX 敏感字符串检查并人工复核。
- [官方 MCP／Skill 标准与产品子集不完全一致] → 分开标注标准要求和当前产品约束；不把扩展字段、传输支持、可执行权限自动等同。

## Migration Plan

这是静态文档变更：构建并运行契约测试后随现有文档站构建流程上线；无需数据迁移。若发现误导性内容，可仅回退本次新增页面、导航和链接，不影响既有 API 页面与运行时。
