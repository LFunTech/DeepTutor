# 为第三方开发者补齐 Capacity 开发规范

## Why

现有文档站详细描述企业 API，却没有按扩展类型说明第三方开发者应如何编写 Capacity；`capability`、Tool、Skill、知识库和 MCP 等概念容易混淆，也容易把本地扩展点误认为企业入口已开放的能力。本变更只补齐面向开发者的规则、边界和示例，不扩展运行时契约。

## What Changes

- 增加 Capacity 开发规范目录及九个独立页面：MCP、Tool、Skill、知识库、自定义 Agent／Turn Capability、对话循环扩展、可视化扩展、阅读扩展、CLI 工具集成。
- 各页统一说明**当前 DeepTutor 代码已实现的完整开发契约**：适用场景、交付结构、全部关键字段与约束、输入输出、兼容与限制、权限与资源边界、失败处理、可验证示例、验证清单以及当前企业适用状态。示例仅辅助说明，不能代替规范正文。
- 增加类型选择与关系说明，区分可复用扩展、对话请求中的受权资源选择，以及非 Capacity 对象；将相关入口从文档首页、能力选择页和侧边栏连通。
- 增加文档契约校验，阻止未开放能力被写成已可通过企业 API 安装、选用或执行，并保留现有 15 个 HTTP 接口与 11 个 WebSocket 命令目录不变。
- **不包含** OMS/TMS 上传、审核、安装、发布、治理步骤；不更改 API、权限、后端、管理页面或流水线。

## Capabilities

- New Capabilities：无。本变更是纯文档和文档校验，设置 `skip_specs: true`。
- Modified Capabilities：无。不改变任何产品行为或已发布协议。

## Impact

- 仅改 `docs-site/` 与本 OpenSpec change；可能更新站点导航、开发者页面、文档测试和 README。
- 企业正式接入仍以现有第三方 HTTP／WebSocket 页面为准；扩展开发规范不构成新的企业安装、发现或执行 API。
- 以当前源码和现行提案核对格式与可用性，但不将内部实现或尚未交付的管理能力写入公开页面。

## 状态

2026-09-27：用户已确认页面范围及“本次只写开发规则、不写发布”的边界；首版页面已落地。用户复审指出首版过度依赖最小示例、未完整记录已实现规范；本变更继续修订，直至各页能独立指导开发。
