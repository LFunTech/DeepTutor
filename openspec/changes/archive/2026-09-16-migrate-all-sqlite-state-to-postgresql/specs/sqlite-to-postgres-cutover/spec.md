## Purpose

规定从既有 SQLite、同步退出的 PocketBase 数据及首切片 PostgreSQL 基础升级到全量 PG-only 应用的安全迁移与切换契约，确保源数据只读、身份归属与跨域引用完整、失败和重试可审计，并防止回退丢失新数据或恢复已撤销的权限。

## ADDED Requirements

### Requirement: schema 升级受控且历史连续

应用 schema/default-data 变更 SHALL 使用统一版本化迁移入口、互斥和历史校验；已应用迁移内容不得被修改或用另一套历史伪装。应用启动 MUST 只验证版本和实际结构/权限，不自动执行 DDL 或旧文件迁移；运行角色不得取得迁移权限。

#### Scenario: 干净安装与首切片升级
- **WHEN** 迁移在空 PG 或已有 schema 1 身份/会话数据上执行并重放
- **THEN** 得到相同目标结构和连续校验历史，原数据/引用保留，无重复初始化或账号覆盖

#### Scenario: 迁移中断或目录漂移
- **WHEN** 迁移失败、并发执行或实际约束/权限与声明不一致
- **THEN** 互斥/事务保护不留下假成功版本，验证明确失败且业务不能在坏 schema 上启动

### Requirement: 导入源必须只读且归属明确

旧数据 SHALL 通过独立离线入口读取获授权的一致性快照，记录源 ID/指纹/版本和 tenant/owner/资源映射。源文件、WAL及关联状态 MUST 不被导入器改写、修复或自动升级；未知归属/版本、源变化和映射冲突必须报告并阻止切换，不能默认归管理员。

#### Scenario: 无归属或不一致源
- **WHEN** manifest 缺少用户映射、存在重复歧义或 SQLite/WAL 快照不一致
- **THEN** plan/verify 报告具体问题，不修改源、覆盖目标或允许业务切换

#### Scenario: 只读规划
- **WHEN** 操作者仅执行源检查和导入 plan
- **THEN** 返回各域/owner/版本、冲突及预计处理信息，不调用旧 Store 初始化、运行模型或启动后台 writer

#### Scenario: 快照仍依赖缺失 WAL
- **WHEN** 提供活动数据库路径、未声明 sidecar 或无法证明完成的备份制品
- **THEN** 拒绝作为导入源，不凭数据库可打开或单表计数推断一致，不用忽略锁的方式读取活动源

### Requirement: PocketBase 退出必须有存量交接

系统 SHALL 对同步退出的 PocketBase 后端提供获授权只读导出及离线 PG 导入，覆盖本应用已支持集合、身份/资源映射、会话/消息/事件与文件引用。导出必须取得统一停写/一致性依据，使用稳定分页与完整性校验，复用同一源清单、批次和映射机制；不得删除/改写远端服务、导入旧认证 token 或默认覆盖目标账号。

#### Scenario: PocketBase 用户升级默认入口
- **WHEN** 原用户使用 PocketBase 保存业务数据并升级到 PG-only
- **THEN** 可通过受控导出/导入将其获授权历史和引用迁入 PG，旧字符串记录 ID 正确映射，目标凭证受控设置而不是仅报 backend 不支持后搁置历史

#### Scenario: 导出分页期间源变化
- **WHEN** 源未停写、读取权限不足或集合/文件清单与导出摘要不完整
- **THEN** 该批次失败并阻止切换，不把不一致的分页结果当完整快照，不扩大导出权限到其它用户业务集合

### Requirement: ID 冲突和跨域引用必须整体处理

导入 SHALL 保留无冲突的既有目标身份/资源；对源库间重复的整数/文本 ID 建立稳定、可追溯的映射，不覆盖目标记录。所有父子消息、摘要锚点、turn/event、题库、学习、阅读和其它纳入域引用 MUST 一致重写并验证。导入后的新写 ID 不得与已导入记录冲突。

#### Scenario: 两个用户源库使用相同 ID
- **WHEN** 两个获授权源中的消息或条目都有相同 ID
- **THEN** 目标记录按来源和 owner 正确区分，所有引用及旧→新报告一致，不能串到他人的记录

#### Scenario: 目标已有数据或坏引用
- **WHEN** 导入遇到目标 ID 冲突、缺父节点或不合法跨域关系
- **THEN** 不覆盖已有业务；合法冲突使用稳定映射，坏关系明确阻断该批次验证而非静默丢弃

### Requirement: 导入幂等且未完成批次不可见

导入 SHALL 持久化批次/源指纹/映射/进度并支持有界分块恢复；目标处于受控维护状态，所有入口 MUST 不读取未完成批次或并发业务写入。相同源重试只复用已确认结果，源变更不能覆盖切换后的 PG 更新；完整校验后才可受控开放。

#### Scenario: 分块导入中断后重试
- **WHEN** 导入在中间批次被取消或进程退出后以同一 manifest 重试
- **THEN** 从已确认进度恢复、不重复记录，业务仍不可见，完整验证前不释放维护门禁

#### Scenario: 全域发布失败
- **WHEN** 准备数据已验证但向正式业务数据的最终发布因任一领域约束/连接失败而中断
- **THEN** 所有该批正式变更原子回滚，运行角色不能直接读取准备数据，其它已完成批次和既有目标不受影响

#### Scenario: 切换后重放旧源
- **WHEN** PG 已产生新更新后再次提交旧导入请求
- **THEN** 返回原批次结果或明确冲突，不把旧 SQLite 内容覆盖到当前 PG 状态

### Requirement: 验证和切换必须覆盖全量业务

切换前 MUST 停止全部原 writer，验证源一致性、每域/owner计数与内容摘要、跨域关系、ID/事件/游标及敏感渠道状态。默认 Web/CLI/SDK/后台与可选渠道 SHALL 在零 SQLite 环境完成真实 PG 行为验证，不能仅凭表计数或企业 chat smoke 放行。

#### Scenario: 行数一致但语义错误
- **WHEN** 行数匹配但分支、题库分类、阅读链接、cron 时区或 Matrix 密钥/信任恢复错误
- **THEN** 验证失败且不切换，不以抽样聊天成功代替相关域完整验证

#### Scenario: PG-only 制品放行
- **WHEN** 全部源验证、功能矩阵、权限/故障测试和默认安装制品测试通过且获得切换批准
- **THEN** 使用同一 PG-only 制品启用业务，旧 SQLite 仅保留为受控备份/离线源，不再有运行 writer

### Requirement: 回退恢复不得丢新数据或复活旧权限

PG 已有新业务写入后 MUST NOT 直接回退旧 SQLite/PocketBase。恢复 SHALL 使用兼容 PG 制品或获批准的备份/资源恢复流程，保持维护态、更新外置认证世代并核对禁用/撤权/凭证状态；不确定的任务/渠道派发不得自动重复。记录实际恢复范围和损失窗口，不宣称未验证的 HA/RPO/RTO。

#### Scenario: 产生 PG 新写后回退
- **WHEN** 新版故障而 PG 已包含旧 SQLite/PocketBase 没有的数据
- **THEN** 仅执行兼容 PG 的受控回退/恢复，不能启用 SQLite/PocketBase backend 或丢弃新增记录

#### Scenario: schema 1 原地升级后尚无业务新写
- **WHEN** 已原地升级 PG schema，但旧应用只兼容升级前的精确结构
- **THEN** 不直接启动旧构建，只允许已验证兼容新 schema 的回退制品，或经批准恢复完整升级前 PG 备份与匹配应用；不能跳过 schema 验证伪造兼容

#### Scenario: 恢复旧快照
- **WHEN** 备份后发生用户改密/禁用、设备撤销或外部任务派发，再恢复备份
- **THEN** 普通业务保持关闭直到身份/设备与不确定执行核对完成，旧密码/token/设备权限不自动恢复，渠道不自动重发
