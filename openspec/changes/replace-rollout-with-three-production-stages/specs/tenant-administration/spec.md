## Purpose

明确第二阶段交付的多租户产品与每租户管理体验，复用现有 DeepTutor 界面而不是重建多个应用，并确保外部身份、用户资源、权限、配额及运行任务在同一部署内具有可验证的隔离边界。

## ADDED Requirements

### Requirement: 先验证一个真实租户的最终集成

系统 SHALL 先在稳定的单租户存储基线上完成一个真实 EduPlus2 租户的最终登录、身份绑定、业务访问、权限及撤权闭环，再开放多个租户；不得使用临时认证方案或省略权限来提前放量。

#### Scenario: 首租户接入验收
- **WHEN** 已绑定租户的真实用户从 EduPlus2 工作台进入
- **THEN** 可按权限聊天及访问 KB/附件，退出或撤权后正确拒绝，原资源所有权/对象引用不变，未绑定租户仍被拒绝

#### Scenario: 开放第二个租户
- **WHEN** 首租户最终接入已经验收且拟开放多租户生产
- **THEN** 仍需先完成双租户隔离及各自管理界面 G2 验证，不因单租户登录成功就视为已完成多租户

### Requirement: 可信身份与端到端租户隔离

阶段二 SHALL 验证 EduPlus2 身份、当前业务态和权限并映射稳定内部租户/用户，HTTP、WebSocket、服务集成、对象下载、检索与后台任务 MUST 使用已授权 scope，缺失或伪造 scope 不得降为默认租户或全局管理员。

#### Scenario: 跨租户访问
- **WHEN** 租户 A 用户或管理员提交租户 B 的资源、对象、会话或任务 ID
- **THEN** 访问被拒绝且不暴露 B 数据，即使两租户具有相同用户名、外部 eui 或 KB 名称

#### Scenario: 停用或撤权
- **WHEN** 租户、用户或权限已停用/撤销
- **THEN** 旧 token、长连接和后台任务不能继续获得新访问权限，缓存失效；必要授权依赖失败时拒绝放行

### Requirement: 每租户自己的管理界面在第二阶段完成

系统 SHALL 基于现有管理界面微调租户标识、资源范围与权限入口，使每租户管理员管理本租户 KB、授权、允许的配置与模型，不复制独立代码/部署，且不依赖第三阶段运营后台。

#### Scenario: 租户管理员正常访问
- **WHEN** 租户管理员打开本租户管理入口
- **THEN** 显示本租户信息和可管理资源，保存操作影响本租户实际运行状态，不能显示平台凭证或全部租户管理入口

#### Scenario: 权限与自定义角色
- **WHEN** 自定义角色获得某管理能力或无该能力的用户尝试访问
- **THEN** 前者菜单与 API 可达，后者入口不可见且直调 API 返回拒绝；管理员默认授权不依赖单一身份类型 claim

### Requirement: 治理后端先于运营界面

阶段二 SHALL 提供受保护可审计的租户开停、授权、配额、必要数据同步及事件幂等入口，并在已选择运行模式下保持执行正确；使用多执行者时 MUST 先通过独立 G-H，不以第三阶段运营界面尚未完成为由省略治理后端。跨租户治理 API 开放前 MUST 已具备可信平台身份、具体能力、目标租户校验及审计，不得等运营界面阶段才补授权。

#### Scenario: 尚无运营后台
- **WHEN** 阶段二需要开通新租户或调整配额
- **THEN** 通过授权管理 API/运维入口操作并留审计，不要求手工改库或临时开发另一套后台

#### Scenario: 请求落入其他 Pod
- **WHEN** 已通过 G-H 的多执行模式中，已有 turn 的订阅、事件重放、取消或用户回复由另一 Pod 接收
- **THEN** 仍正确鉴权并作用于目标 turn，故障任务可明确结束/恢复，重复请求不重复写业务状态或重复扣额度


### Requirement: 固定 workspace 检索路由与可信调用

系统 SHALL 在检索前校验 tenant/owner/grant/策略，再使用内部 tenant/KB/index-version binding 和受限内部凭证路由至固定 workspace LightRAG Server。默认实例池属于共享检索子系统，不复制整套租户 DeepTutor；动态多 workspace 服务层不是原版 Server 配置能力，容量不满足时 MUST 先评审并验证替代实现，不混合未授权语料或删减范围。

#### Scenario: 同名 KB 或同地址别名
- **WHEN** 两租户有相同 KB 名称，或多个连接指向同一 Server 地址
- **THEN** 以可信 binding 判断实际 namespace/归属，错误绑定拒绝；不得假定 KB 名称或代理 header 能切换固定 workspace，也不得跨租户取 top-k 后过滤

#### Scenario: 篡改路由或服务凭证
- **WHEN** 用户提交任意 Server URL/workspace，或调用凭证与 actor/KB/操作/policy_version 不符、过期或已撤权
- **THEN** 网关在检索前拒绝，不下放 Server key；原始查询/文档/图及兼容 API 均不能通过未受控网络入口绕过授权

#### Scenario: 不同可见范围的图语料
- **WHEN** 个人 KB 和共享 KB 或不同租户的资料具有不同访问范围
- **THEN** 不先合并成同一图再过滤结果，KV/vector/doc_status/graph/cache 使用一致隔离 namespace，引用下载仍检查当前权限


#### Scenario: 资源重命名或同名重建
- **WHEN** 已授权 KB 重命名、重建索引，或被删除后创建同名新 KB
- **THEN** grants 绑定不可复用的内部资源 ID，原 KB 重命名/索引升级不改变授权，新 KB 不继承旧 grants；名称/旧标识仅在可信 scope 中显式映射
