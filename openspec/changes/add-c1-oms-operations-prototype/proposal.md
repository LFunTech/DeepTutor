# Agent 平台 OMS 高保真原型与总体契约重构

## Why

现有 `/oms/prototype` 是围绕“只读治理 + Token 计费/欠费”制作的开发态演示：卡片和说明堆叠，不能作为逐级深入的管理后台，也没有覆盖 DeepTutor 的 Agent、工具、知识、运行资源。该原型及关联六个实施 proposal 中“Provider 在 DeepTutor `/settings` 维护”“OMS 不管理租户服务授权”“按每百万 Token 计费并欠费停机”等目标，均已被用户后续决策取代。不能在旧目标上继续美化页面或实施 API。

需要先建立一套面向普通运营人员、以 DeepTutor 现有资源和设置语义为来源的 Agent 平台信息架构，再交付高保真、可复用但不冒充真实 OMS 的前端原型。DeepTutor 是本地部署产品，不是云服务“用户端”；OMS 与 TMS 是面向学校/企业云服务的两个独立部署前端。租户生命周期仍由 EduPlus2 权威事件决定；平台与租户的管理责任必须分清。

## What Changes

- **OMS 是企业平台管理入口**：维护平台服务与供应商、连接/Secret、Agent 能力、工具与集成、知识与内容基础能力、运行资源、服务供给、租户服务授权/额度、实际用量和审计。普通运营与高权限配置人员看到各自获授权的页面和动作。
- **五类资源目录均有类型化新增**：模型与服务、Agent、工具与集成、知识基础能力、运行资源均提供权限受控的新增草稿入口；服务下还可新增 Provider profile/模型。新目录记录先展示为未生效草稿，未接入真实执行者前不得冒充可调用服务。内置注册表条目不作为可在线复制或创建的代码。
- **Skill 按 owner 分层、按完整包管理**：云端 Skill 的 owner 仅为 `global` 或指定 `tenant`，来源另分 DeepTutor builtin、OMS ZIP 包提交、受控 Hub 导入和租户 ZIP 包提交。OMS/TMS 创建及更新非 builtin Skill 均以包含 `SKILL.md` 的 ZIP 包为提交物，不接受单文件或仅填写正文；名称、说明、标签、依赖等 Skill 内容元数据只从包内 `SKILL.md` 解析，不由后台表单重写。owner、来源、审核状态、授权与包摘要则由可信平台上下文生成，不信任包内自报。builtin 在 OMS 中是不可编辑的 global 条目，云端默认不授权任何租户；OMS 可按需授权，目标 TMS 即可只读查看和使用，无成员/应用二次分配。非 builtin 包须审查发布；TMS 提交与已授权 global（含 builtin）同名的包时须先告知并经管理员确认，运行时本租户版本优先。DeepTutor 本地的 builtin 自动发现与个人 Skill 行为不因此改变。
- **TMS 管租户内部事务**：用户、应用、知识库/文件等租户实例及在 OMS 授权范围内的内部使用分配。OMS 可查看必要的脱敏跨租户状态，但不替 TMS 编辑私有内容、注册 client/app 或直接开停租户。个人偏好及普通学习内容不升级为 OMS 平台管理资源。
- **本地产品与云端管理面分离**：本地部署继续保留 DeepTutor Web 与其设置功能；云端 OMS、TMS 各自构建和部署，不把 DeepTutor `web/` 当生产管理前端。仅云端企业装配不开放旧 `/settings` 平台管理页及核心管理写 API 的直连旁路；保留确有必要的非管理公共/个人偏好接口。DeepTutor 的字段、provider descriptor、运行校验和执行者仍是语义来源，不复制第二套核心逻辑。
- **OMS/TMS 共享前端组件，不共享部署或数据权限**：同仓共享管理后台设计规范、基础控件及服务列表/详情等业务组件；例如 OMS 与 TMS 使用同一 OCR 服务列表组件及搜索、分页、状态、详情交互，由各自页面提供受权限约束的数据和操作。OMS 专有供应商凭据、采购成本和跨租户数据不得进入 TMS 接口或共享组件的数据契约。TMS 原型由独立的 `add-b2-tms-management-prototype` 规划。
- **品牌色跟随 EduPlus2 而非写死**：OMS 使用 EduPlus2 无租户参数的 `platform_default` 品牌，TMS 使用可信当前租户的品牌；两端共享 `palette` 到管理 UI token 的映射。认证服务域名按环境配置，请求失败或颜色不合法时回退天蓝色，不把某个租户的主题当作 OMS 平台主题，也不让主题查询参数成为租户授权依据。
- **统一资源语言**：外部采购形成“服务供给”；向租户授予的额度使用同一个列表，以获取方式区分“充值/赠送”；授予只形成未使用承诺，真实服务调用才产生“实际消耗”。平台展示可授予额度、已承诺未使用额度、可信实际用量及待核对量，不使用仓储式入库/出库话术。
- **每项可调用服务均需授权与配额**：赠送额度优先于充值额度；服务额度用尽只停止对应服务的新调用，供给不足另行标识；登录、管理、历史查询和其他仍可用服务不受牵连。复合 Agent 的底层服务消耗只计一次。不能把非 Token 单位强行折算为 Token，缺可信用量不能按零核销。
- **取消租户计费与欠费方案**：本目标不设置每百万 Token 售价、不计算租户费用、不建立欠费停机或 EduPlus2 欠费模型资格闭环。采购凭证/成本如在 OMS 内部保留，属于高权限供给管理元数据，不产生租户账单；具体成本分摊待独立口径确认。
- **扩展优先、核心修改例外**：优先在 `extensions/enterprise/`、企业装配与受控管理界面扩展。确实缺少通用接入点时，先提交逐处的替代方案、最小 upstream-neutral seam、上游合并风险、安全和真实入口回归证据供严格审阅；获批准前不改 DeepTutor 核心，不用 monkey patch。
- 本 change 交付总体 IA、DeepTutor 设置与资源对照、云端独立部署及共享组件契约、权限/计量边界和**开发环境专用**高保真可复用 OMS 前端原型的验收目标；不宣称真实 OMS API、持久总账、供给/配额执行、迁移或生产上线已完成。当前 DeepTutor `web/app/oms/prototype` 仅是旧评审载体，须标为待替换，不得当成新方案验收。

## Capabilities

### New Capabilities

- `enterprise-platform-operations-admin`：Agent 平台 OMS 的信息架构、平台/租户权责、供给—授权—用量契约、云端独立前端/共享组件、企业管理入口关闭和开发态原型边界。

### Modified Capabilities

无。本 change 的 delta 只定义新目标，不直接修改已发布的 DeepTutor 核心能力；若后续实现影响已有正式 spec，由相应实施 change 明确补 delta。

## Impact

- 云端 OMS 单独构建/部署，可由云端 `/oms` 入口承载；真实平台身份、API、权限和数据面验收前保持“尚未启用”。目标开发态 `/oms/prototype` 由 OMS 应用承载并使用独立演示数据适配器；现有 DeepTutor `web/app/oms/prototype` 不再是生产应用落点，迁移/退役须单独验证开发可达与生产 404。共享管理组件包由 OMS/TMS 两个独立应用消费，禁止让 TMS 直接依赖 OMS 应用源码。
- 需重订现有六个实施 proposal 的范围：EduPlus2 change 收敛到租户生命周期；平台治理 change 扩展平台管理权限；全服务 Provider 设置移入 OMS；真实 usage 总账扩展可信原生单位；原 Token 计费/欠费 change 由“服务供给、租户授权、额度、消耗”方案替代；操作界面 change 改为完整 Agent 平台管理。**在这些实施 proposal 完成重订并分别获批准前，不按旧 tasks 开工。**
- `docs/enterprise/02-*`、`11-*`、`12-*`、OpenSpec 旧实施提案及现有 `web/app/oms`、`web/app/tms` 规划页仍含单体 Web/旧权责/计费叙述，后续同步任务须逐处修订；当前文档重构不修改运行态、DB/OpenFGA/Keycloak、核心代码或已运行的开发服务。
