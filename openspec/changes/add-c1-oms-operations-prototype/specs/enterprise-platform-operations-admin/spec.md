## Purpose

定义云端 Agent 平台 OMS 的目标信息架构和权责：以 DeepTutor 现有能力为执行核心，由 OMS 管平台资源、服务供给、租户服务权益与真实用量；TMS 管租户内部事务。OMS/TMS 是独立部署的云端前端并复用同一业务组件；DeepTutor 本地 Web 不是云端管理端。此 delta 仅规划与开发态高保真原型，不代表企业 OMS、资源采购、配额执行或权限已上线。

## ADDED Requirements

### Requirement: OMS 必须成为企业平台管理面而 DeepTutor 管理入口不得直连

云端企业部署 SHALL 将 DeepTutor 平台级管理迁入获授权 OMS 扩展界面/API，涵盖服务/供应商、连接/Secret、Agent 能力、工具/集成、知识基础能力、运行资源、供给、租户服务授权/额度、用量和审计；DeepTutor SHALL 保留现有资源语义与真实执行。云端企业环境 MUST NOT 仅通过隐藏导航来关闭旧 `/settings` 或核心管理写接口；直接 URL、API、CLI/SDK 等旁路 SHALL 由企业装配/访问边界阻止。确需保留的公共 UI/个人偏好接口 SHALL 逐项白名单且不能产生平台管理写能力。DeepTutor 本地部署 SHALL 保留其本地 Web 设置功能，不因云端 OMS 的禁用策略失去原有管理能力；非企业发行的核心行为不得因企业专用规则被硬编码改变。

#### Scenario: 直接访问旧设置入口
- **WHEN** 企业租户用户或平台人员绕过 OMS/TMS 直接打开 DeepTutor 旧管理页或调用其管理写 API
- **THEN** 企业入口拒绝或不装配该能力，不能通过旧角色/路由顺序绕过 OMS 动作权限
- **AND** 正常聊天、学习及明确白名单的非管理个人偏好仍可用

#### Scenario: 本地用户管理 OCR 解析选项
- **WHEN** 本地部署用户打开 DeepTutor Web 的文档解析设置
- **THEN** 本地原有配置路径仍可使用，云端 OMS 的租户、采购和额度权限不会注入本地界面

### Requirement: OMS 与 TMS 必须独立部署且复用同一管理业务组件

OMS 与 TMS SHALL 分别构建、部署和发布云端前端，不以 DeepTutor 本地 Web 构建或互相依赖对方应用源码交付。两端相同的服务列表/详情交互 SHALL 消费同一受版本管理的共享业务组件和设计规范，包括列语义、搜索筛选、分页、状态、进入详情及加载/空/错误/无权限呈现；各自 SHALL 从自身获授权 API 提供数据与允许的动作。共享组件的输入 MUST NOT 含 TMS 不可见的供应商成本、平台 Secret 或跨租户明细；TMS 后端不得仅依靠前端隐藏这些字段。独立发布 SHALL 验证共享组件及契约版本兼容。

#### Scenario: OCR 列表跨两个前端复用
- **WHEN** OMS 和 TMS 分别展示 OCR 服务列表
- **THEN** 两端使用同一业务组件提供一致的共用列、筛选、分页、状态和详情导航，且组件变更经两端构建与交互回归
- **AND** OMS 可在专有容器展示有权查看的平台供给信息，TMS 只收到本租户可见的服务数据和动作

#### Scenario: 独立前端部署
- **WHEN** 仅发布 OMS 前端新版本
- **THEN** TMS 与 DeepTutor 本地 Web 的运行部署不被替换，TMS 使用的共享组件版本仍与其 API 契约兼容

### Requirement: OMS 与 TMS 必须共享 EduPlus2 品牌主题契约但隔离作用域

OMS 与 TMS SHALL 使用相同的 EduPlus2 公开品牌响应校验和 `palette` 到管理 UI token 的映射；认证服务根地址 SHALL 按部署环境配置，不能硬编码测试域名。OMS SHALL 请求无租户参数的平台默认主题，不因打开某个租户详情而切换为该租户品牌。品牌读取 SHALL 由各前端服务端完成，颜色须经格式和可读性校验后用于首次渲染；失败 SHALL 回退完整、可读的天蓝色主题，不中断管理。品牌查询的 `school_code`、`tenant_id` 或返回的学校名称 MUST NOT 被解释为业务授权或租户 lifecycle 事实。

#### Scenario: OMS 使用平台默认品牌
- **WHEN** EduPlus2 无租户参数的品牌接口返回 `code=0`、`brand_source=platform_default` 和有效 `palette`
- **THEN** OMS 使用该平台调色板，查看任意租户详情时仍保持平台主题
- **AND** `fallback_reason=context_missing` 不使有效调色板被误判为失败

#### Scenario: 环境切换或品牌接口故障
- **WHEN** OMS 所在环境配置不同认证服务域名，或该环境的品牌响应超时、缺字段、颜色不合规
- **THEN** 请求只发往该环境配置的固定品牌路径；失败时完整回退天蓝色主题，登录和管理路径仍可用

### Requirement: OMS、TMS、EduPlus2 和个人资源必须按权威分层

OMS SHALL 管平台目录、供给、租户服务授权与全部配额配置、跨租户脱敏运营；TMS SHALL 管本租户用户、应用、知识库/文件实例，并只能只读查看本租户统一配额清单、详情与真实消耗。配额授予、赠送、充值、调整、撤销及应用/成员配额上限等写入均不属于 TMS。个人会话、伙伴实例与学习内容继续受 owner/既有授权保护。EduPlus2 签名事件 SHALL 是租户开通/暂停/恢复的权威，OMS MUST NOT 直接改写租户 lifecycle 或借配额耗尽停用整个租户。

#### Scenario: TMS 尝试越过平台授权
- **WHEN** 租户管理员尝试写入配额、为应用设置配额上限，或使用 OMS 未授权的服务
- **THEN** 服务端拒绝，TMS 不能用本地显示/配置扩大平台权益或修改 OMS 配额事实

#### Scenario: 租户服务额度耗尽
- **WHEN** 一项服务的租户有效额度耗尽而其他服务仍有额度、租户 lifecycle 正常
- **THEN** 只有该服务的后续调用因额度不足被拒绝；登录、OMS/TMS 管理、历史查询及其他服务不因该额度耗尽而停用

### Requirement: OMS 必须覆盖 DeepTutor 的平台资源而不复制运行语义

OMS SHALL 以 DeepTutor 当前 SettingsStore、后端 provider descriptors、CapabilityRegistry、ToolRegistry 和相关资源 API/执行路径为来源，组织模型与服务、Agent/能力、工具/集成、知识/内容基础能力、运行资源五类平台资源。配置 UI MUST 遵守各服务现有条件字段、候选项和生效/测试逻辑，不得把搜索、任务模型、语音、图像、视频及解析/外部 Agent 等强套统一 LLM 表单。目录资源的版本/授权管理与可计量服务的额度管理 SHALL 分开；平台人员不得因目录权限读取学员私有正文或 Secret 明文。

#### Scenario: 平台管理员维护非 LLM 服务
- **WHEN** 获授权人员在 OMS 查看并调整搜索、文档解析或语音服务
- **THEN** 页面逐级进入该服务现有语义对应的配置与生效记录，候选/条件来自真实 descriptor
- **AND** 执行者确认 active 前不得显示“已生效”，不通过旧 DeepTutor 管理页面提交

### Requirement: 服务供给、租户额度和实际消耗必须形成可追溯闭环

OMS SHALL 按服务、真实供应商资源范围、可核实原生单位与有效期记录采购/补充形成的服务供给；按租户和服务在**同一个额度列表**记录获取方式为“赠送”或“充值”的授予。授予 SHALL 形成已承诺未使用额度，不得算作实际消耗；租户真实使用后才同时归集租户额度和相应供应商供给。系统 MUST 防止超额授予、并发双重使用、同一次调用重复消耗，并保留来源、操作者、变更原因、版本与审计。赠送有效额度 MUST 优先于充值额度，已发生消耗不得追溯重分摊。

#### Scenario: 采购、授予和使用的区别
- **WHEN** 采购形成某服务供给，OMS 再向租户授予一笔赠送及一笔充值额度
- **THEN** 服务供给和可授予量分别更新；两笔额度出现在同一个租户额度列表，并以获取方式区分
- **AND** 授予动作不出现在实际消耗列表；只有 DeepTutor 真实执行后才生成实际消耗关联

#### Scenario: 赠送优先且用量跨两笔额度
- **WHEN** 单次真实调用量超过租户剩余赠送额度但未超过赠送与充值额度之和
- **THEN** 消耗记录关联该调用及两笔额度，先耗尽有效赠送部分，再使用充值部分；供应商供给总消耗仅记录该调用的真实用量一次

#### Scenario: 供应商资源无法可信换算
- **WHEN** 外部合同只有金额型余额、credits 或无法与服务执行单位核对的值
- **THEN** OMS 不得把该数值假装为可精确授予/消耗的 Token 或调用额度；显示待确认的供给/换算状态，直到受控契约和对账可用

### Requirement: 每项可调用服务须有适合的配额与真实计量边界

每项可调用服务 SHALL 明确授权、配额单位、有效期/周期、调用前准入和真实用量来源。Token 型调用以可信 provider usage 或可核验对账为依据，非 Token 服务保留其原生单位；若没有可靠更细单位，MAY 采用经执行边界验证的调用次数，不得用字符估算或任意单位转换。未知结果 SHALL 标为待核对并保留受控预留，不能按零消耗释放。复合 Agent 顶层执行与其模型/工具子调用 MUST NOT 对同一服务用量重复扣减。服务供给不足与租户额度不足 SHALL 有不同状态和影响范围。

#### Scenario: 流式模型调用没有最终 usage
- **WHEN** 一次流式调用已开始但最终 usage 缺失且远端消耗无法确认
- **THEN** 调用、额度预留和供给关联保持待核对；OMS 不显示零实际用量，也不虚构精确剩余额度

#### Scenario: Agent 调用两项底层服务
- **WHEN** 一个 Agent 流程分别调用 LLM 与搜索服务
- **THEN** 两种服务按各自可信单位分别记一次实际消耗；Agent 流程状态可以独立观察，但不能再将相同用量作为顶层 Agent 消耗重复扣除

### Requirement: OMS 页面必须按对象自上而下逐级深入

OMS SHALL 提供工作台、租户与权益、资源目录、资源供给、用量与运行、审计与治理的分组导航。每个资源对象 SHALL 先有受权限保护的列表，再通过明确“查看详情”进入详情及下级关联列表；同一对象只有一个规范详情，关闭详情时保留原列表筛选。原型的对象详情 SHALL 在列表上方以可关闭的抽屉逐级呈现，不得仅靠整页跳转完成日常查看；新增、编辑、授权、额度和供给等维护表单 SHALL 以独立模态框弹出，不得在列表或详情抽屉内展开撑开空间。撤销、发布及其他需复核动作使用确认模态框；取消复核返回原表单并保留填写内容。直接访问对象深链仍 SHALL 显示相应列表与详情抽屉。主页面优先显示业务影响、状态、下一步和一张主要列表，技术字段和说明默认折叠。后端提供状态 display descriptor，缺失时安全降级；加载、空、无权限、待核对、同步延迟和错误不得互相冒充。

#### Scenario: 运营人员查看租户的一次调用
- **WHEN** 有权限的运营人员从租户列表进入租户详情，再选服务、用户和单次调用
- **THEN** 各层分别显示该对象的概要和下级列表，最终明细可追溯服务、provider/model、真实用量来源及赠送/充值额度消耗
- **AND** 页面不会把所有层级的卡片和说明同时堆在租户首页

#### Scenario: 从列表查看并维护平台资源
- **WHEN** 有管理权限的运营人员从服务、连接、Agent、工具、知识基础能力或运行资源列表查看对象并编辑平台可维护设置
- **THEN** 列表保持在抽屉背后，详情在抽屉中逐级呈现；配置表单在独立模态框中显示，不改变列表或详情布局，本地演示保存后可回读新状态
- **AND** 无权限角色不见写入动作；内置注册表身份、租户生命周期、实际用量和审计事实不被伪装成可直接编辑的数据

### Requirement: OMS 原型须显式演示平台维护而非只读目录

OMS 原型 SHALL 为租户服务授权与统一额度、服务与 provider profile/模型配置、供应商连接、Agent/能力、工具/集成、知识基础能力、运行策略和服务供给提供符合对象权限与 DeepTutor 现有语义的可发现维护入口。内置能力和工具的注册表身份不得被伪装成可在线增删的运行代码；可维护的是平台配置草稿、使用策略、授权范围及受控发布流程。演示写入 SHALL 更新本地可回读状态，且持续标记为本地模拟；不得把草稿冒充执行者已确认的 active 配置。高风险网络、Secret 与发布操作 SHALL 与日常额度操作分权；用量和审计只作事实查询/核对，租户生命周期只查询 EduPlus2 权威结果。

#### Scenario: 审计员查看可维护对象
- **WHEN** 只读审计角色查看任一平台资源、供给或租户权益
- **THEN** 能在授权范围内查看详情，但无新增、编辑、调整、撤销或发布按钮，也不能由原型角色切换获得真实后台写权限

#### Scenario: 维护草稿并确认敏感动作
- **WHEN** 平台管理员编辑解析服务、Agent 可用策略或供应商连接草稿，或者运营人员授予额度
- **THEN** 表单保留各自的 DeepTutor 条件字段与业务校验，保存后从列表或详情可回读本地演示结果
- **AND** 对权益、供给和发布等影响范围较大的操作先以模态框展示对象与变化并可取消；不会发送真实管理 API 请求

### Requirement: OMS 五类平台资源目录必须支持受类型约束的新增草稿

OMS 原型 SHALL 在模型与服务、Agent 与能力、工具与集成、知识与内容基础能力、运行资源五类列表提供权限受控且可发现的新增操作，并为服务下的 Provider profile/模型、供应商资源方案和供给批次提供相应新增入口。不同资源类型 SHALL 使用符合 DeepTutor 现有字段与执行边界的表单模态框；成功保存的本地演示对象 SHALL 回到原列表、可进入唯一详情继续维护，并清楚显示来源、类型与未生效状态。名称/标识重复、必填项缺失或越权创建 SHALL 被拒绝。内置 Capability/Tool/Skill 的注册表身份、未知服务适配器、运行引擎、租户私有 KB、EduPlus2 租户、实际用量及审计事实 MUST NOT 被伪装成可在线创建并立即生效；尚无真实适配与执行者确认的对象只可为草稿、待接入或待校验。

#### Scenario: 平台管理员新增外部 Agent 与服务配置
- **WHEN** 平台管理员分别从 Agent 列表和服务的供应商配置列表发起新增
- **THEN** 类型专用模态框校验输入，本地草稿分别出现在对应列表和详情中，保留原列表筛选
- **AND** 草稿不自动注册进 DeepTutor 的内置运行 registry，也不宣称服务或 Agent 已可供租户调用

#### Scenario: 审计员或运营人员尝试新增高权限资源
- **WHEN** 无平台配置权限的角色打开五类目录或猜测演示新增路径
- **THEN** 不出现新增动作且不能改变本地目录状态；普通运营仍只可处理被授权的供给和租户权益

### Requirement: OMS 必须将平台 Skill 作为独立可管理目录

OMS SHALL 在工具与集成下提供独立的 Skills 列表与详情；云端 Skill owner SHALL 仅为 `global` 或指定 `tenant`，并与内置/人工/Hub/上传来源分离。获授权平台配置人员 SHALL 能以包含 `SKILL.md` 的 ZIP 包创建 `global` Skill 草稿、提交同名新包版本、查看版本与审查状态、提交发布申请并配置拟授权租户；受控 Hub 导入须取得并校验真实 Skill 包。创建/更新不得接受单独 `SKILL.md`、纯文本正文或由表单填写/覆盖 Skill 名称、说明、标签和依赖；这些内容元数据 SHALL 从包内 `SKILL.md` 解析。owner、来源、审核状态、授权和包摘要 SHALL 由可信平台上下文确定而非信任上传内容。所有原型演示动作仅改变本地状态。内置 Skill 不得被直接改写，未完成安全审查的导入项不得自动启用或设置不受控 `always` 注入；发布申请不得冒充真实 active。`global` Skill 只有已发布且获得 OMS 对当前租户的有效授权，才能进入该租户 TMS 的安全投影及运行时可用范围；**授权生效后不要求 TMS 再向成员/应用分配**。`tenant` owner 的 Skill 由该租户 TMS 管理，发布后仅本租户可用且不得提升为 `global`。若 tenant 与 global 同名，tenant 管理员上传前确认后可保留两条独立记录，运行时本租户已发布 Skill 优先，global 不得在该租户被同名调用静默选中；OMS 对已有同名 tenant Skill 的租户补授权 global 时也须提示覆盖关系。本地个人 Skill 不因 OMS 目录管理而变成云端第三种 owner。Skill 自身不产生独立 Token 消耗，使用过程中的模型/工具调用仍按底层服务计量。

#### Scenario: 提交平台 Skill 包并配置拟授权范围
- **WHEN** 平台管理员提交符合 DeepTutor 包结构的 ZIP，包内唯一 `SKILL.md` 含有效 YAML frontmatter 的 `name`、`description`、可选元数据和非空 Markdown 说明，再配置一所学校为拟授权对象
- **THEN** OMS 从 `SKILL.md` 回读只读元数据、正文及包内资源清单，登记未审查的本地草稿和拟授权记录；TMS 不把该草稿呈现为可用 Skill，其他租户不可见
- **AND** 未经真实审核发布与运行时权限校验，不显示“已生效”或声称该 Skill 已进入 DeepTutor 的 `read_skill` 可用集合

#### Scenario: 拒绝伪造或不完整 Skill 包
- **WHEN** 平台人员只输入正文、选择单个 `SKILL.md`，或提交缺少有效 `name`/`description`/正文、目录名与声明不一致、多个 `SKILL.md`、危险路径、链接、加密、损坏或超限的 ZIP
- **THEN** 原型拒绝保存 Skill 草稿并指出包内问题；服务端正式实施时必须重新校验，不能把浏览器预检结果当安全审查或让包内自报的 owner/状态生效

#### Scenario: 按问题类型展示可操作的 Skill 包错误
- **WHEN** ZIP 缺少 `SKILL.md`、frontmatter YAML 无法解析、存在 macOS 辅助文件、路径穿越、重复资源、内容损坏或浏览器不支持解压
- **THEN** OMS 的共享包预检提示 SHALL 区分包结构、`SKILL.md` 格式、包内容、路径安全限制、ZIP 数据损坏与浏览器兼容性问题；已知条目 SHALL 显示具体路径并给出修复建议，YAML 错误尽可能显示行列位置
- **AND** 缺少 `SKILL.md`、YAML 格式错误或普通辅助文件不得笼统标为“安全问题”或“危险路径”；再次点击保存不得覆盖已经显示的具体预检原因

#### Scenario: 更新平台 Skill 版本
- **WHEN** 管理员更新非 builtin 的 global Skill
- **THEN** 只能提交 `name` 相同且重新通过校验的新 ZIP，保留旧包的版本/摘要和授权审计；新版本重新进入待审核，不在线改写原 `SKILL.md` 或借旧发布状态立即运行

#### Scenario: 查看已发布且已授权的平台 Skill
- **WHEN** 评审者打开配对演示案例中的 OMS 平台 Skill 发布/授权记录及目标学校 TMS
- **THEN** TMS 仅以只读安全投影展示预置已发布且授权该校的 Skill，该校可直接使用而无成员/应用二次分配；未授权租户不可见，独立原型间不宣称新增草稿实时同步

#### Scenario: 给已有同名 tenant Skill 的租户授权 global Skill
- **WHEN** 平台人员拟向已有已发布同名 tenant Skill 的租户授权 global Skill
- **THEN** OMS 告知该租户的同名调用仍优先使用 tenant Skill；授权可保存但不覆盖、不删除租户 Skill，也不把 global 误标为当前运行时版本

### Requirement: DeepTutor builtin Skill 必须作为只读 global 条目按租户授权

OMS 原型 SHALL 将 DeepTutor 打包提供的 builtin Skill 显示为 `owner=global, source=builtin`，与 OMS 人工创建/Hub 导入来源区分，并展示不可编辑的内容版本/摘要、`requires` 运行条件和逐租户授权状态；不得复制成可编辑 Skill 或创建第三种云端 owner。云端首次接入、新增 builtin 及未获 OMS 授权的租户 SHALL 默认为不可用；只有经平台复核的打包版本并获目标租户授权，才可进入该租户的可用投影。正式企业运行时 MUST 将该授权同时用于 Skill 清单、`read_skill` 正文/参考文件、显式请求及 `always` 自动注入，不能只在页面隐藏；已授权但 `requires` 不满足时须显示不可用。DeepTutor 本地部署的 builtin 自动发现与个人 Skill 覆盖行为 SHALL 保持不变。打包版本/内容变化 MUST 有复核与可追溯记录，不得沿旧授权静默激活新内容；本原型只演示这些状态，不声称已拦截真实运行时。

#### Scenario: 新租户尚未获 builtin 授权
- **WHEN** 新租户进入云端 TMS，而 OMS 尚未授权 `pdf` builtin Skill
- **THEN** TMS 不将其列为可用 Skill；未来正式运行时的清单、`read_skill` 和 `always` 路径均不得读取它，本地 DeepTutor 用户仍按本地规则使用 builtin

#### Scenario: builtin 已授权但运行条件缺失
- **WHEN** OMS 已向租户授权需要 shell sandbox 的 builtin Skill，而目标执行环境缺少该 sandbox
- **THEN** OMS/TMS 区分“已授权”和“运行条件不足”，不得宣称可以使用或绕过 `requires` 门禁

#### Scenario: 程序升级改变 builtin 内容
- **WHEN** 新 DeepTutor 版本携带同名但内容摘要变化的 builtin Skill
- **THEN** OMS 标记待复核及影响租户，未经复核不得让新内容沿旧授权静默替代原版本

### Requirement: 权限与敏感数据必须贯穿菜单、API 和导出

企业 OMS SHALL 以可信平台主体和动作级权限保护平台配置、Secret、服务供给采购、租户授权/额度、用量核对及审计。前端菜单/按钮与后端能力一致，但前端隐藏不能代替后端鉴权；tenant_admin、普通用户、auditor 或只有部分权限的 operator 不得越权写入或跨租户读取。Secret、私有正文和敏感采购数据 SHALL 在 API、导出、日志与演示数据中隔离/脱敏。

#### Scenario: 租户管理员直调额度 API
- **WHEN** tenant_admin 伪造平台角色、目标租户或前端隐藏按钮请求 OMS 授予额度
- **THEN** 服务端拒绝且不泄露其他租户是否存在

### Requirement: 企业功能必须优先扩展，核心补丁须先审阅

企业专属逻辑 SHALL 优先位于 `extensions/enterprise/` 与企业装配层，不能使用 monkey patch、`sitecustomize`、导入顺序副作用或全局单例替换。若现有 DeepTutor 扩展点无法覆盖真实调用、配置生效或管理入口关闭，MUST 在修改核心前提交替代方案审计、最小 upstream-neutral seam、受影响入口、上游合并风险和验证覆盖，并经严格审阅批准；未批准不得实施核心补丁。

#### Scenario: 配额校验缺少通用调用 seam
- **WHEN** 现有扩展层无法在 CLI、HTTP/WS、SDK、后台的真实服务调用边界一致执行额度准入
- **THEN** 实施方先提交核心 seam 审阅，不在 orchestrator/registry 等核心路径硬编码 OMS 或租户业务规则

### Requirement: 开发态原型不得冒充真实 OMS

目标云端 `/oms/prototype` SHALL 仅在 OMS 独立应用的开发环境提供可复用 OMS 界面的高保真交互预览，演示数据/动作与组件分离且显式标注；不得读取真实跨租户 OMS 数据或执行生产写入。生产请求 SHALL 返回真实 HTTP 404；云端 `/oms` 在可信权限、真实 API、供给/额度/用量闭环验收前保持未启用。现有 DeepTutor Web 的旧只读计费演示 SHALL 在迁移后退役，MUST NOT 被声明为本版原型或业务验收完成。

#### Scenario: 评审演示额度路径
- **WHEN** 评审者在开发环境从租户列表进入额度详情，模拟赠送/充值及一次实际消耗
- **THEN** 原型可展示统一额度列表、赠送优先与关联供给/调用，但所有数据和结果均明确为本地演示
- **AND** 相同组件以后可以接真实受权限保护的数据适配器，不把 demo fixture 混入正式路径
