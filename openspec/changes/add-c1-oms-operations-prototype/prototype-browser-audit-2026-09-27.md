# OMS / TMS 原型浏览器审计（2026-09-27）

本记录仅验收独立前端的**合成原型**。浏览器中看到的身份、学校、连接、模型、额度、用量及审计均非真实接口回读；不能据此声称真实权限、凭据、发布或模型调用已交付。

## 操作与视觉复核

- 开发态 OMS `/oms/prototype` 及 15 个一级列表、TMS `/tms/prototype/demo-school` 及 11 个一级列表，在 1280×800 和 390×800 两档访问；均有页面标题、无 `pageerror`，文档无横向溢出。
- 逐个点击每个一级列表首行的**全部**具名动作：OMS 每档 42 次，TMS 每档 27 次，共 138 次。每次仅出现一个抽屉或确认框，Escape 可关闭；不再用整页跳转代替详情专题。覆盖服务、学校、连接、Skill、供给、用量、授权、成员、应用、知识库等列表。其他行、嵌套关系及异常数据由交互测试补充，并非逐条人工目测。
- OMS 连接模态框、文档 OCR 配置模态框、平台人员授权与嵌套选人模态框，在窄屏下检查可见性、焦点回到触发按钮、两次 Escape 的层级关闭和无横向溢出。TMS 账号目录与应用服务模态框在窄屏下检查目录故障提示、关闭与表单操作；额度页无写入按钮。
- 从 OMS 学校授权进入服务、关闭返回原学校专题；OMS/TMS 工作台待办关闭返回、搜索/筛选及前进后退由 `local-navigation`、`atomic-list-actions` 和关联对象自动化测试覆盖。TMS 跨学校 code 直达返回 HTTP 404。
- 浏览器完成“百炼连接 → Provider Profile → Qwen 模型草稿”及“Docling OCR 配置草稿”的本地回读；TMS 应用增加已授权服务经确认后回读。**均停留在演示草稿/关系，不代表实际调用。**
- 审计员在 OMS 看不到新增服务动作；无权限角色得到拒绝状态。TMS 普通成员无法进入管理清单，学校额度页无授予/充值入口。
- TMS 窄屏角色/权限切换栏原先挤压断字；改为两行「标签—选项」栅格，重新截图核对。平台蓝与学校紫使用提供的 EduPlus2 `palette` 做 CSS 视觉预览；首屏受控请求、无效颜色/故障回退及跨学校拒绝由服务器布局/品牌单测验证。CSS 预览不是一次真实登录后的学校品牌端到端验收。
- 生产构建在独立端口启动后，以 HTTP 请求检查 OMS 和 TMS 原型根、列表及学校详情路由，全部返回 **404**；开发态入口仍分别返回 200。

## 同日首位 TMS 管理员来源修订（合成原型）

用户指定签名真实 `subscription.created.actor.user_id` 为首位管理员身份来源，DeepTutor Enterprise 程序按一次性学校栅栏与本人 TMS 登录匹配后授权。开发态 TMS 原型撤下旧“学校负责人甲/乙复核”演示，改为事件 actor 待本人匹配、已匹配、其他人登录、actor 缺失/system/null 与控制台 mock 状态；只有已匹配合成状态可模拟激活，界面明确说明切换选项不构成真实权限。定向前端测试先见旧交互失败，改版后 **23 passed**；真实事件处理/API/本人登录均未由该原型验证，生产原型仍 404。前述浏览器审计是旧交互快照；新版复核如下。
