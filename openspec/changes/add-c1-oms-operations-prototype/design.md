# 设计：Agent 平台 OMS 信息架构与原型

## 决策与现状

用户确认 DeepTutor 首先是本地用户本地部署产品，没有云端“管理端/用户端”划分；OMS/TMS 是面向学校、企业云服务的独立管理产品。云端 OMS 取代企业装配中的平台管理入口，TMS 负责租户内部事务；DeepTutor 本地 Web 仍保留本地设置功能，核心保留 agent-native 运行及配置/执行语义。此前“OMS 只读 Provider + Token 计费/欠费”和“OMS/TMS 共用 DeepTutor Web 生产构建”的设计均已失效。本 change 的 [现状审计](readiness-audit.md)与 [设置属性对照](settings-attribute-inventory.md)仅说明当前源码支持什么，不证明新管理路径已可用。当前 DeepTutor `web/app/oms/prototype` 是旧目标的演示，不满足本设计；`web/app/oms` 是未启用规划页，均非云端 OMS 生产应用。

## 产品、部署与共享前端边界

| 交付物 | 构建/部署 | 管理身份与数据 | 可复用边界 |
| --- | --- | --- | --- |
| DeepTutor 本地 Web | 随本地产品独立交付 | 本地用户管理自己的服务连接/偏好；无云端平台/租户供给权限 | 现有设置实现是字段和执行语义基线；是否消费云端组件须按本地体验单独评审，不强制引入云端壳 |
| 云端 OMS | 独立前端应用、镜像/发布与入口 | 可信平台主体；跨租户仅获授权管理元数据 | 消费共享管理设计系统、服务业务组件与契约；平台专有容器/动作留在 OMS |
| 云端 TMS | 独立前端应用、镜像/发布与入口 | 可信当前租户主体；只读写本租户授权范围 | 与 OMS 消费**同一来源、兼容版本**的共享组件包，不从 OMS 应用源码复制或跨应用 import |

两个云端前端使用共同的 React、TypeScript、Next.js 技术基线，但**各自独立构建**；共享包采用同仓 workspace/版本化包方式消费，不以运行时跨应用加载组件。目标代码组织例如 `extensions/enterprise/frontends/apps/{oms,tms}` 与 `extensions/enterprise/frontends/packages/{admin-ui,service-components,api-contracts}`；精确路径、包管理器及 Ant Design 或定制 headless 控件的取舍，须在原型实施前用管理后台视觉、可访问性和两端构建实证确定，不能在两应用里混用两套基础组件。上述工具选择可以调整，但“独立构建/部署、共享包、无应用间源码依赖”不可改变。两应用可由云端网关映射 `/oms`、`/tms` 或独立域名，入口选择不应让它们再次合入 DeepTutor 本地 Web 构建。现有 `/oms/prototype` 仅作迁移前开发评审载体；高保真原型的目标位置是 OMS 独立应用的开发态入口，TMS 原型由 [`add-b2-tms-management-prototype`](../add-b2-tms-management-prototype/proposal.md) 规划。生产原型路径必须返回真正 HTTP 404。

共享分两层：`admin-ui` 拥有表格、筛选、分页、面包屑、表单、状态和主题 token；`service-components` 拥有 OCR 服务列表/详情等**复合业务组件**，统一列语义、交互和加载/空/错误状态。OMS/TMS 页面容器分别获取自身 API 数据、做权限判断、提供允许的操作和必要的专有侧栏；不能在共享组件中堆 `isOms/isTms` 分支，也不能仅靠隐藏列保护敏感数据。共享列表的输入 DTO 只含两端均可见的安全字段；采购成本、平台 Secret、跨租户明细只允许 OMS 专有 API/容器接收，TMS API 不得返回。组件不持有凭据、租户覆盖参数或跨域会话。共享包的变更要同时构建/测试 OMS 与 TMS；独立部署时通过明确兼容版本避免一端仍使用旧组件/契约而表现不一致。OCR 只是复用验收样例，实际 OCR 的设置字段按 DeepTutor 当前解析引擎事实及后续服务 proposal 确认，不虚构独立 OCR provider 已实现。

**不选的路线**：两套前端复制页面会造成交互漂移；单个 Next 构建用角色切换 OMS/TMS 违背独立部署；让 TMS 直接 import OMS 页面会把平台专有数据/权限带入租户应用。云端管理后端先以企业扩展中的模块化 API、服务与数据权限作为逻辑边界，单进程还是多部署由实施提案依据隔离、扩缩容及发布需求裁决，不能因前端分开就复制两套 DeepTutor 核心。

### EduPlus2 品牌主题契约

OMS 与 TMS 共享品牌响应解析、颜色校验和 CSS token 映射，但独立取得各自作用域的主题。各部署使用服务端环境变量 `EDUPLUS2_BRANDING_BASE_URL` 指向当前环境的 EduPlus2 认证服务根地址，拼接固定的 `/api/v1/public/branding`；不得把 `eduplus-auth-test.f123.pub` 写死为生产地址，也不得接受浏览器提交的任意品牌域名。OMS 不传 `school_code`、`tenant_id`，采用接口返回的 `brand_source=platform_default` 平台主题；查看租户详情不会把整个 OMS 切成该租户色。用户提供的测试响应中平台 `palette.primary=#1A56DB`，只作为契约样例，不作为固定 UI 常量。

两端由自身服务端取得公开品牌响应，再在首次 HTML 渲染时设置共享管理 UI 的 CSS 自定义属性，避免浏览器跨域依赖和初次渲染后的主题闪烁。响应须为 `code=0` 且包含有效的 `data.palette`；映射 `primary`、`primary_hover`、`primary_light`、`primary_bg`、`sidebar`、`sidebar_hover`、`text_on_primary`，颜色仅接受完整十六进制格式并校验文字与主色/侧栏的可读对比度。`primary_color` 是响应中的冗余主色提示，不覆盖有效 `palette.primary`；`fallback_reason` 不单独表示请求失败（平台样例为 `context_missing`）。不能把返回文本直接拼入 CSS；`logo_url`、学校名称、登录文案和 ICP 信息不属于本次颜色切换。

请求设置超时和短时缓存（原型目标不超过 5 分钟），下一次页面加载或服务端重新渲染在缓存到期后更新，不承诺已打开页面实时换色。网络失败、非成功响应、字段缺失或颜色/对比度不合规时，整套回退到可读的天蓝色默认主题，保留成功/警告/错误的独立语义色；失败不能阻断 OMS 登录、导航或管理。平台主题和租户主题使用相同 token 契约，不复制两套 CSS。直接在浏览器跨域请求会引入 CORS 与闪烁，构建时固定颜色无法随租户变化，均不采用。品牌读取只影响展示，不改变身份、租户生命周期、服务授权或 DeepTutor 核心设置。

## 权责与资源层级

| 对象 | 写入权威 | OMS | TMS / DeepTutor 业务界面 |
| --- | --- | --- | --- |
| 租户开通、暂停、恢复 | EduPlus2 签名生命周期事件 | 查看来源、生效/同步异常；不直接开停 | TMS 查看本租户状态；DeepTutor 在适当入口执行租户资格 |
| 平台资源目录与配置 | OMS 获授权平台角色，执行语义复用 DeepTutor | 模型/服务、Agent 能力、工具/集成、知识基础能力、运行资源的目录、版本、测试、发布与审计 | TMS 只选择被允许的租户范围；用户内容不移入 OMS |
| 供应商连接、凭据、服务供给 | OMS 高权限角色 | 配置/轮换 Secret 引用、确认真实执行生效、记录外部资源方案及采购/补充 | 不读取 Secret 或扩大平台供给 |
| 租户服务授权与额度 | OMS 获授权角色 | 授予/调整/撤销服务访问权及全部赠送/充值额度配置 | TMS 只读查看本租户统一配额清单、详情和消耗明细；不新增、调整、撤销配额，也不设置应用/成员配额上限 |
| 实际用量 | DeepTutor 可信服务调用与企业总账 | 跨租户脱敏汇总和逐调用核对，关联供给与租户额度 | TMS 查看本租户获授权用量；普通用户只看自身可见信息 |
| 用户、应用、KB/文件、伙伴实例、学习内容 | TMS/业务 owner 及既有 EduPlus2 身份权威 | 仅必要的脱敏状态/用量/影响；不管理正文或跨租户私有资源 | TMS 管租户实例；DeepTutor 保留使用者的创建、阅读和个人偏好 |

OMS 的“管理”指企业平台目录、配置、供给、租户权益和运营观察，不意味着平台人员可阅读学员会话、知识库正文或文件内容。主题、语言、学习档案等个人偏好不进 OMS；登录前需要的 `/api/settings/ui` 非管理读路径可以保留最小能力，不得成为设置写入旁路。

## 一致术语与计量关系

| 页面术语 | 精确定义 |
| --- | --- |
| 服务供给 | 外部供应商按服务、provider/model、原生单位、有效期等提供的可核实资源；采购/补充形成可追溯供给批次 |
| 可授予额度 | 同一可互换资源范围内，已取得且有效的供给扣除已实际消耗、已向租户承诺但未使用的额度和未完成预留后的可再授予部分 |
| 租户额度 | 某租户某服务的单条授予记录；统一列表中以“获取方式=赠送/充值”区分，包含来源、单位、数量、有效期、已使用、剩余与审计 |
| 实际消耗 | 一次可信服务执行的原生单位用量；同时归集到对应租户授予记录和真实供应商供给批次，不把授予动作记为消耗 |
| 待核对用量 | 真实用量缺失、流中断、异步任务未完成或跨系统确认不确定；既不记零也不伪装已结算 |

外部采购 → 形成服务供给 → OMS 授予租户额度 → DeepTutor 在实际调用时计量 → 消耗归集 → 预警与补充，是业务闭环，不使用“库存/入库/出库”作为 UI 话术。赠送额度先于充值额度；同类中按有效期/确定性的版本顺序使用。已发生的消耗不因之后的赠送、过期或调整而重分配。过期/撤销只能释放尚未使用的承诺，不可改写原始消耗。

**不得超额承诺或双重扣量。**授予只占用可授予额度，不减少已采购供给的实际剩余；一次服务执行最终只形成一次供给消耗，但可按赠送/充值拆分其租户额度消耗。并发调用在可信 tenant/user/service/operation 上做幂等预留和最终核对；失败或取消仅在确认没有远端消耗后释放，未知结果继续保留待核对。Token 型流式调用如无法给出可执行上限，不能宣称严格硬配额；必须有上限预留/保守准入与真实 usage 核对。非 Token 服务用经 DeepTutor 执行路径验证的原生单位，最少可准确统计调用次数；不把供应商金额余额、credits 或时长无契约地换算为 Token。同一服务的不同供应商/模型资源若单位、适用范围或有效期不相容，不合并可授予量。

租户额度耗尽只阻断该租户对应服务的新调用；平台服务供给不足是不同的跨租户异常。两者均不改变 EduPlus2 租户 lifecycle、不注销会话、不阻断 OMS/TMS 登录/管理或其他仍可用服务。复合 Agent 顶层执行可以用于观察或独立已定义的运行资源限额，但其下游模型/工具实际消耗不得重复记为顶层服务的同一单位。此方案**不计算租户费用、不定义欠费停机或每百万 Token 售价**。供应商采购成本如需内部可见，必须独立授权且不能冒充租户账单；金额归集规则不在本原型 change 中发明。

## DeepTutor 资源覆盖

[资源与作用域对照](resource-scope-inventory.md)记录源码入口、OMS 平台管理对象、TMS/个人边界和计量适用性。平台一级目录涵盖：

1. **模型与服务**：connections、LLM、task、embedding、search、TTS、STT、imagegen、videogen；另列文档解析/RAG、视频学习外部服务，保持各自不同的配置/计量规则。
2. **Agent 与能力**：CapabilityRegistry、外部子智能体、伙伴/角色模板的共享目录、依赖、版本和租户可用范围；个人伙伴实例及会话仍归属 owner。
3. **工具与集成**：ToolRegistry、MCP、CLI apps、外部连接的共享目录、授权和服务依赖；**Skills 是该组下独立可见的一级列表**，不藏在工具详情或伪装成可执行 Tool。个人安装或使用偏好不自动提升为平台配置。
4. **知识与内容基础能力**：解析/检索引擎、附件/存储/记忆策略、受控资源容量；具体租户 KB、文件和正文仍遵守 TMS/业务 owner 与既有资源隔离。
5. **运行资源**：workspace、sandbox、cron、后台任务及状态；平台级安全/容量策略与只读运行观察分开，高风险网络/部署配置仅受控角色可见/变更。

不是所有目录对象都是可消耗服务：有可验证计量边界的服务才有执行额度；纯模板/策略以版本和授权管理。所有**可调用服务**都须定义配额单位、准确计量路径、待核对策略和服务调用准入，不因当前设置页有某个字段就宣称企业执行闭环已完成。精确 Provider 属性仍以 [设置属性对照](settings-attribute-inventory.md) 及后端 descriptor 为准。

### 类型化新增与 Skill 层级

五类平台目录均提供“新增”入口，但新增的对象类型不同，不能用一张通用表单伪装运行能力：

| 目录 | 可新增的平台草稿 | 不得伪装的动作 |
| --- | --- | --- |
| 模型与服务 | 现有 DeepTutor 服务类型的 Provider profile/模型与连接；新的外部服务接入定义须关联适配器方案 | 未实现的服务适配器或未知计量单位立即变为可调用服务 |
| Agent 与能力 | 外部 Agent 接入、共享 Agent/角色模板及其依赖/可用范围 | 在线创建内置 `CapabilityRegistry` 代码 |
| 工具与集成 | MCP/CLI/外部工具接入；平台 Skill 另设清单 | 在线创建内置 `ToolRegistry` 代码、将 Skill 当作 Tool 执行 |
| 知识与内容基础能力 | 平台解析、检索或存储配置/策略实例 | 在 OMS 创建租户私有 KB 或读取文档正文 |
| 运行资源 | 沙箱、工作空间、调度等平台运行策略/环境配置实例 | 在线创建新的运行引擎或直接变更高风险网络配置 |

统一流程为列表新增 → 类型专用表单模态框 → 本地草稿出现在原列表 → 详情抽屉可回读、继续配置和查看发布条件。标识在同作用域去重，字段随类型校验；未完成适配、权限、安全测试与执行者确认时，状态保持“草稿/待接入/待校验”，不算 active。供给批次与供应商资源方案另从资源供给列表新增，补充数量仍从现有供给详情发起；租户由 EduPlus2 创建，OMS 仅新增授权和额度；用量、审计事实不可新增。高权限配置人员可新增平台资源，普通运营仍仅维护获授权的租户权益和供给，审计员只读。所有演示写入仅保存在原型本地状态。

DeepTutor 当前 `SkillService` 提供用户层 Skill 的创建/更新/删除、标签和 Hub 安装；内置 Skill 只读，管理员分配的 Skill 对用户只读（`deeptutor/api/routers/skills.py`、`deeptutor/multi_user/skill_access.py`）。这不是现成的云端平台/租户级 Skill 后端。云端 Skill 的 **owner 仅 `global` 或指定 `tenant`**，来源另为 `builtin`、人工创建、Hub 导入或租户上传；本地个人 Skill 不自动成为云端第三种 owner。

OMS 原型新增独立 global Skill 列表：非 builtin 的创建与更新版本只能提交 Skill ZIP；受控 Hub 导入须以实际取得的 Skill 包为依据，不能仅凭 URL 与手填说明伪造已导入条目。表单在本地解析 ZIP 中唯一的 `SKILL.md`，展示只读元数据、正文预览、参考文件/脚本清单和校验结果；不提供正文或元数据文本框。内容元数据（包括 `name`、`description`、可选 `tags`/`requires`/`always` 等 DeepTutor 字段）以 `SKILL.md` frontmatter 为唯一来源；包内正文以该文件的 Markdown 部分为准。ZIP 允许 DeepTutor 现有导入器接受的根级 `SKILL.md` 或单一命名目录包，后者目录名必须与 frontmatter `name` 相同；接收后均按 `name/` 规范化。`name` 符合 Agent Skills 规范，`description` 和非空说明正文必填；无效 YAML、重复/多根 `SKILL.md`、路径穿越、符号链接、加密/损坏/膨胀 ZIP、重复条目、超限或不允许的文件类型须拒绝。支持 `references/` 等资源及 DeepTutor 白名单内的文本脚本，不能因包含脚本就误判为非 Skill；执行仍须经安全审查。原型浏览器预检不是服务端安全结论，不上传、不解压到执行路径，不生成“已安全审核”或可运行状态。未来企业后端须重新解析并校验完整 ZIP，保存不可变包版本与内容摘要，审查后方可发布。参照 [Agent Skills 规范](https://agentskills.io/specification) 的目录与 frontmatter 契约，并与 DeepTutor `deeptutor/services/skill/hub.py`、`service.py` 的包结构/受控导入语义保持一致。

Skill 的 owner、来源、租户、审核/发布状态、授权、不可变包摘要/平台修订号属于**平台治理数据**，只能从可信操作者上下文与校验后的包生成，不采信 ZIP 自报的 `owner`、`tenant` 或状态；这与“Skill 内容元数据全部从 `SKILL.md` 获得”不冲突。官方可选的 `license`、`compatibility`、`metadata`、`allowed-tools` 及 DeepTutor 可选的 `tags`、`requires`、`always` 等若显示，亦只能读自 frontmatter；包未声明语义版本时不得把平台修订号伪装为作者版本。列表与详情展示解析结果，不允许管理员在表单中覆写 `SKILL.md` 元数据。编辑操作改为提交同名新 ZIP 版本并重新审查，不能就地修改已发布包。导入项未通过安全审查不得自动启用，不接受不受控的 `always` 自动注入。只有已发布且获得 OMS 对目标租户的有效授权，Skill 才进入该租户的 TMS 可用投影；**授权即租户可用**，TMS 不再进行成员/应用二次分配，也不能编辑 global Skill 内容或扩大授权。`tenant` owner 的 Skill 由该租户 TMS 提交包、维护版本和发布，发布后只在本租户可用，不需 OMS 再授权，也不能提升为 global。平台/租户草稿均不可在运行时使用。

DeepTutor 随程序提供的 `docx`、`pdf`、`pptx`、`xlsx`、`skill-creator` 是 **`owner=global, source=builtin`** 的只读目录条目：OMS 展示名称、说明、依赖条件、程序版本/内容摘要和逐租户授权状态，只能授权/撤权，不能在线改写或删除打包内容。云端首次接入及新增 builtin 默认**零租户授权**；未授权者在 TMS 及真实运行时清单、`read_skill` 正文/参考文件、`always` 自动注入中均不可见/不可用。即使已授权，仍需满足 `requires`（例如 Office/PDF builtin 的 shell sandbox），不可把“已授权”显示成“运行条件已就绪”。本地 DeepTutor 的自动发现与用户覆盖 builtin 逻辑保持原样，不因云端 OMS 控制而关闭。后续程序升级若改变 builtin 内容，OMS 须展示版本/摘要变化并复核授权影响；正式实现不得让未审阅的新内容借旧授权静默生效。

OMS/TMS 的 Skill 列表共用安全的业务组件，详情与动作分别由各自容器装配。两个原型的本地状态不作实时跨端同步承诺；跨端授权演示使用配对 fixture，OMS 草稿/发布申请不直接出现在 TMS。真实 owner 存储、审核发布、按租户授权及运行时 `read_skill` 校验由后续企业实施提案在扩展层完成；原型不得调用现有用户级 `/api/skills` 冒充租户写入。Skill 身份由 owner 与名称共同确定，同一 tenant 可上传与已授权 global 同名的 Skill，但上传前须显著告知并经租户管理员确认；其已发布版本在该租户运行时优先，global 仍保留但不会被同名调用选中。OMS 后续授权同名 global Skill 时应提示该租户现有版本仍优先，不静默改变选择；TMS 撤销 tenant 版本前提示 global 可能重新成为候选。此优先级必须同时约束清单和 `read_skill` 正文/参考文件；tenant 版本暂不可用时不静默回退 global。Skill 本身不单独核销 Token，底层模型/工具服务按可信用量计量。

## 逐级信息架构与主要路径

```text
工作台
└─ 供给不足 / 租户额度不足 / 执行异常 / 用量待核对事项列表 → 事项详情
租户与权益
└─ 租户列表 → 租户详情
   ├─ 服务授权列表 → 授权详情
   ├─ 额度列表（获取方式：赠送/充值）→ 单条额度详情
   ├─ 使用概况 → 服务 → 用户 → 单次调用详情
   └─ 权益变更记录 → 记录详情
资源目录
├─ 模型与服务列表 → 服务详情 → 供应商配置 / 模型参数 / 生效记录
├─ Agent 与能力列表 → 能力详情 → 所用服务 / 工具 / 租户可用范围
├─ 工具与集成列表 → 工具详情 → 连接 / 授权 / 依赖
├─ Skills 列表 → 平台 Skill 详情 → 来源 / 标签 / 内容版本 / 租户授权 / 审查状态
├─ 知识与内容基础能力列表 → 详情 → 解析 / 检索 / 存储策略
└─ 运行资源列表 → 详情 → 策略 / 状态
资源供给
└─ 服务供给列表 → 服务供给详情
   ├─ 供应商资源方案 → 方案详情
   ├─ 采购与补充记录 → 记录详情
   ├─ 已承诺租户额度 → 租户额度详情
   └─ 实际消耗 → 单次调用详情
用量与运行
├─ 租户用量列表 → 服务 → 用户 → 调用列表 → 调用详情
└─ Agent 执行 / 后台任务列表 → 脱敏执行详情
审计与治理
└─ 授权 / 配置发布 / 额度变更 / 采购记录列表 → 记录详情
```

入口共享同一对象详情，不复制“租户配额”或“服务供给”的另一套页面。每级先有可搜索/筛选/分页的列表，行内“查看详情”在原列表上打开抽屉；下级对象替换抽屉内容并提供返回上级，不叠多层抽屉。直接打开详情深链也显示“列表＋抽屉”，关闭后回到保留筛选的位置。新增、编辑、平台策略、权益、额度和供给操作均在独立表单模态框中完成，列表与详情抽屉保持原布局；复杂服务设置使用宽度受限、内容独立滚动的模态框。需要复核时暂时隐藏表单模态框并显示确认模态框，取消复核恢复原表单及填写值，确认后关闭表单并回读结果。撤销与发布等直接操作只显示确认模态框。一个页面一个主要对象/主表，默认不展开技术字段、代码、配置依据或大量说明卡。普通运营先看到影响、状态、剩余额度和下一步；高级配置和脱敏技术详情仅在有权限且主动展开时出现。加载、空结果、无权限、同步延迟、用量待核对和失败分别呈现；空结果不可等同于零用量。

原型维护矩阵：平台管理员可编辑服务配置草稿、供应商连接及 Agent/工具/知识/运行策略；日常运营可授予或撤销租户服务资格、授予/调整/撤销未使用额度、补充服务供给；审计角色只读。高风险网络、Secret 引用和配置发布独立于普通运营，原型不接受真实 Secret，也不声称本地草稿已发布。内置能力/工具的运行注册表身份只读，管理的是其平台策略/范围而非代码定义；实际调用用量、审计事实和 EduPlus2 租户 lifecycle 只读。演示动作必须改变本地可回读状态；有副作用的动作有对象/变化复核与取消路径。正式权限仍由后续 API proposal 固定，前端显隐不能代替服务端鉴权。

## 权限、入口与数据边界

`ops.oms.access` 是基础入口；平台角色分别获得租户/资源/供给/额度/用量/审计的读权限及对应管理动作。建议将服务/凭据发布、供给采购、租户授权/额度、用量核对分为独立能力；具体 key、默认角色、OpenFGA/Keycloak 映射由后续实施 proposal 固定。平台 admin 可经授权配置高风险服务/凭据，operator 只具备授予的日常权限，auditor 只读；tenant_admin 不因 TMS 身份获得跨租户 OMS 能力。菜单/按钮只是体验，企业 API 每次先验可信平台主体与动作能力，再绑定目标租户，白名单返回；Secret、私有正文、采购敏感金额不会因跨租户查询或导出泄露。

云端企业装配层须关闭 DeepTutor 原管理页面、原管理 API 和 CLI/SDK 等可绕过的云端管理路径；不能只隐藏菜单，也不能仅以路由顺序盖住核心端点。**本地 DeepTutor Web 的设置/管理功能不因此被删除或禁止。**`/api/settings/ui` 等云端确需保留的非管理路径逐项白名单复核。新增云端管理入口需要独立前端部署、后端权限、默认/自定义角色、迁移和 403/200/越权负例闭环；本 change 仅写契约，不执行迁移。

## 扩展优先与严格核心审阅门禁

新企业规则、PG 总账、额度/供给、权限和 OMS 管理 API 优先位于 `extensions/enterprise/`；前端由独立 OMS 应用及共享组件包组成，不改写 DeepTutor 本地设置组件的业务语义。当前核心设置/Registry/Provider 代码仅作语义来源；不复制第二套模型、工具或 Agent 实现，不使用 monkey patch、`sitecustomize`、导入顺序副作用或全局单例替换。若需让本地 Web 也使用新的通用服务组件，须证明不会把云端租户概念或额外管理权限注入本地产品，并按上游可合并性审阅。

每处确实无法扩展的 DeepTutor 核心改动必须**先审阅，后实施**：列出缺失扩展点和替代方案、拟改行/入口、upstream-neutral 的最小 seam、受影响的 CLI/HTTP/WS/SDK/后台调用、上游合并冲突风险、权限/隔离/用量/会话/审计相关正负例及当前 upstream 兼容检查。未获明确审阅通过不改核心。若守住该门禁后仍无可行方案，标记阻塞而非悄悄修改。

## 原型与实施提案重订

目标云端 `/oms/prototype` 是 OMS 独立应用的开发态评审入口，现有 DeepTutor Web 旧演示必须重做并在迁移后退役。OMS 原型页面消费共享 `admin-ui`/`service-components` 和独立 OMS 容器；演示 fixture/适配器与组件分开，正式 OMS 只有真实 API/平台权限就绪后才能复用同一界面。TMS 独立原型须通过共享 OCR 服务列表等组件的消费证明一致性，而非复制 JSX；两端同一组件在共用列/搜索/分页/详情/状态上的交互和视觉回归都要验证。原型中赠送、充值、授权、采购和配置动作只改变明确标注的本地模拟状态，不执行 API 写入，也不假装真实业务已完成。OMS/TMS 生产原型路径返回真正 HTTP 404；正式入口在真实数据与鉴权交付前继续占位。高保真验收包括桌面/窄屏、键盘、详情钻取、加载/空/错误/无权限/待核对、赠送优先、服务额度耗尽与供给不足的不同结果。
