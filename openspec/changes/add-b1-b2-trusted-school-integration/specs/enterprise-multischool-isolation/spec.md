## Purpose

规定智能体基座在 B1 首校闭环之后开放多学校时，对应用 PG、个人与学校资源、对象和检索服务、缓存及后台任务的一致隔离和 G2 受控放量标准。

## ADDED Requirements

### Requirement: 多学校范围只能由可信绑定派生

系统 SHALL 从已验证会话和当前版本的内部学校绑定派生唯一可信 scope，并在受限事务中设置；请求的学校码、header、body、资源 ID 或外部 `tid` MUST NOT 覆盖它。跨学校运维只能走另行授权、审计的 OMS 目标学校操作，不能使 TMS 或普通会话切换学校。

#### Scenario: 修改 TMS 深链学校码
- **WHEN** 学校 A 会话请求学校 B 的 `/tms/{schoolCode}`、API 或猜测的资源 ID
- **THEN** 页面和 API 均拒绝，不返回 B 的成员、品牌私有上下文、额度、对象或检索结果

### Requirement: 数据面按学校及资源所有权隔离

系统 SHALL 对 PG/RLS、连接池、owner/显式 grant、S3 对象授权、LightRAG workspace/KB/index-version/图检索、缓存、事件订阅和后台任务使用同一可信学校范围；个人私有内容还须独立 owner/grant 检查。检索 MUST 在返回或生成结果前按服务端 scope 隔离，不得先跨学校搜索后由前端过滤。

#### Scenario: 双学校同名资源与连接池交错
- **WHEN** 两所合成学校使用同名 KB、相同外部用户标识，并交错访问同一连接池和检索服务
- **THEN** 各自只得到本校且个人有权的行、对象、引用和图事实；后一个请求不继承前一个请求的 scope

#### Scenario: 低权直接访问检索后端
- **WHEN** 受限执行身份直接请求其他学校的检索 namespace、源文或图关系
- **THEN** 服务端/数据库防线拒绝，不能仅依靠 DeepTutor 查询过滤或 UI 隐藏

### Requirement: 外部生命周期与本地权限取交集

学校可执行状态 SHALL 为已验证外部生命周期、当前学校绑定、本地隔离和适用业务/管理权限的交集。生命周期 Webhook 仅由独立 change 管理，其 mock 投递不得变更真实学校状态；OMS 配额耗尽只能拒绝对应服务的新调用，不能暂停学校登录、管理、历史或其他服务。

#### Scenario: 外部恢复而本地仍隔离
- **WHEN** 学校收到真实有效的外部恢复事件，但本地隔离尚未解除
- **THEN** 新业务调用继续拒绝，外部事件不覆盖本地隔离或授予本产品角色

### Requirement: 初始化和任务重试不可跨校串写

学校初始化、绑定、任务派发、失败重试与资源回收 SHALL 使用持久幂等键、版本栅栏和可信学校 scope；无可信 scope、过期绑定、远端状态不确定时 SHALL 停止副作用并保留待核对状态，不从默认学校、缓存或高权连接继续执行。

#### Scenario: 旧学校任务在解绑后重试
- **WHEN** 绑定版本已经改变，旧任务或重试消息仍携带先前学校标识
- **THEN** 不写入新旧学校资源，留下可审计的拒绝/待核对结果

### Requirement: G2 门禁必须覆盖双学校与全部入口

系统 SHALL 在 B1 完成后，以两所隔离测试学校、各校管理员/普通用户及同校两个普通用户，验证 HTTP/WS、SDK、后台、TMS、OMS 授权边界和 PG/S3/LightRAG/缓存/任务正负例；撤权、停用、错学校、错 client、同名资源、私有 owner、限额与回退均须有证据。多执行者或 HA 若在目标环境启用，必须先满足独立 G-H 一致性门禁。

#### Scenario: 只有单校 API happy path
- **WHEN** 登录和一个 HTTP 调用成功，但双校负例、远端检索隔离或回退未验证
- **THEN** G2 保持未通过，第二所真实学校不放量；单 Pod 成功不视作 HA 验收
