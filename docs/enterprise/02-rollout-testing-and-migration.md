## 执行模型

2026-09-13 修订：企业特有逻辑保持独立扩展包/应用外壳；用户进一步要求取消 local/SQLite，默认 Web/CLI/SDK/后台全部使用 PG，通用 PG 与必要 provider 下沉 core 并收敛旁路。RAG 已确定 LightRAG Server，图检索必需，首发图后端采用用户 fork 的 HugeGraphStorage，A1/A2 完成生产实现与验收。保留 **M1 单租户 Kubernetes → M2 多租户及租户管理界面 → M3 统一运营后台** 三个业务里程碑，研发按 **A1/A2/A3、B1/B2、C1/C2 七个工作包** 推进。工作包是集成验收单元，不是七套系统，也不要求七次生产上线。

[OpenSpec 总纲 tasks](../../openspec/changes/replace-rollout-with-three-production-stages/tasks.md) 是工作包汇总门禁的勾选记录；子提案细项与证据由各自 tasks 记录，只有原项完整范围通过才汇总。首个 [A1 身份与 PG 会话子切片](../../openspec/changes/add-enterprise-pg-identity-session-slice/proposal.md) 已完成 34 项工作区实现与隔离验证；后续[全量 PostgreSQL-only 迁移](../../openspec/changes/migrate-all-sqlite-state-to-postgresql/proposal.md)包含默认入口、全部 SQLite 领域、Matrix 间接存储和只读导入，当前为 55 项待实施任务。其余 A1/A2 仍按总纲完成；子切片或本次规划通过不等于完整工作包/生产验收。

- 生产组件直接替换为最终实现，不建设 SQLite/PVC、文件型多租户、双写或临时认证系统。
- 配置/现有注入/插件优先，通用 PG 在 core、企业特有实现置于 `deeptutor_enterprise` 包；[13](13-deployment-and-upstream-sync.md) 的默认 PG-only 与真实调用清单、[06](06-postgresql-native-store-plan.md) 的 LightRAG 接入验收及服务契约纳入相应工作包，不新增独立重写阶段。
- 复用已选 LightRAG Server 引擎，固定 workspace 实例池纳入 A2 交付，不按租户复制整套 DeepTutor；A1/A2 完成上线验收，不再二选一，也不计划首发后整体迁移另一服务。
- 一个任务覆盖适用的 **数据约束/迁移 → 服务逻辑 → 真实入口 → 权限/异常 → 测试 → 切换说明**，不是仅创建表或编写接口类。
- A1/A2 在集成环境分批验证，A3 汇总验收后才发布 M1；未完整替换的存储状态不能作为正式生产版本。
- B1 先用一个真实 EduPlus2 租户验证最终接入，B2 再开放多个租户；C1/C2 分批完成运营功能，不把 C2 从最终交付范围删除。
- Woodpecker 流水线开发纳入 A3 必交付子环节，从 A1 并行建设；后续阶段复用，不新增业务工作包。
- 可用性、容量和多副本由独立工作线 H 管理，不由租户数量决定，不增加第八个业务工作包。

## M1：单租户 Kubernetes 正式上线

### A1：结构化状态替换

先确认首发功能清单、实际存量和用户归属、目标容量及可用性要求，再固定内部 tenant/user ID、Store/metadata 契约。同步核查配置/插件/容器注入可复用点，登记必须补齐的通用核心 seam 和企业包责任；明确 KB/保留版本数量、已选 LightRAG 的必需图能力与 PG/HugeGraph/S3 存储边界、固定版本、质量/容量/费用及恢复预算，建立真实教材验收集；复用用户 fork 的 HugeGraphStorage，固定包含实现的 commit/digest，确认 tenant/KB 授权粒度与可验证的图隔离策略；同时按 [07](07-resource-isolation.md) 固定文件分类及原文/服务派生副本责任。已有必须上线的能力不得静默删除；可选能力未启用的决定需要记入发布范围，不无限扩展为支持所有上游可选插件。

按可观察行为拆分：

- 本地登录/账号、单租户多用户所有权与受控管理员初始化。
- 创建/继续会话、消息/turn/event 事务持久化；历史、事件重放、regenerate/reply/cancel 等调用路径。
- 设置保存到运行时读取、模型目录/Secret 引用、资源 grants。
- memory、notebook、KB metadata、可编辑资源 metadata、审计等各自真实读写链路。

DeepTutor 应用租户表从第一天具备 `tenant_id`、复合约束和 RLS；平台数据显式分开。独立检索索引使用 [06](06-postgresql-native-store-plan.md) 的 provider namespace/受限凭证/数据库隔离契约，不假设服务 workspace/RBAC 自动等于应用 tenant 列或 RLS。直接 SQLite/JSON 调用不能留在生产旁路。内部 ID 后续只绑定外部身份，不重写资源所有权。

**A1 验收**：每项 PG 行为有真实入口、并发/错误/所有权测试及旧生产写路径退出证据。还未接通 S3/RAG 时只能认定 A1 工作包完成，不能认定单租户产品可发布。

### A2：文件与检索替换

A1 契约确定后可并行开发，按附件、生成物、知识库等完整行为接入：

1. S3-compatible 流式读写、私有对象授权、短 TTL URL 和失败重试，在目标服务验证。
2. 对象额度 PG 预留/核算/释放、pending/ready 状态及孤立对象清理，在 M1 完成；不是等待 B2 的 token/并发治理。
3. 附件上传/metadata/预览/下载/删除与所有权闭环。
4. scratch 下载→文件工具处理→S3 上传→PG 提交→成功事件；Pod 中断不得虚报产物成功。
5. KB 原文、解析物、索引、召回、源文引用、删除及重建全链路，含需要的 KV/图状态。
6. 可编辑 skills/personas 及首发必需高级能力的正文、配置、执行读取统一接入最终存储。

A2 按 [06 上线门禁](06-postgresql-native-store-plan.md) 将已选 LightRAG Server 接入最终企业路径，在 G1 前完成真实教材质量/成本/容量、完整生命周期、个人私有/双租户隔离、低权运行及恢复验收。不再把选择 provider 作为待办；WeKnora 不建首发企业实现，图使用用户 fork 的 HugeGraphStorage 而非 PGTableGraphStorage/Neo4j，不能静默禁图或换后端绕过失败。

企业包接通 LightRAG 的 PG/Secret binding、可信调用凭证、查询前授权、文档 API、引用映射与删除/重建；S3 保存原文/解析物及登记的服务副本。验证固定 workspace 实例生命周期、容量、写互斥；KV/vector/doc_status 存 PG、图存 HugeGraph；必须具备独立数据库防线，不以接通 URL、API key 或安装 pgvector 代替验收。

稳定 namespace 使用内部 tenant/KB/index-version，不使用绝对 scratch 路径。已有本地 `lightrag` 文件索引仅按真实存量评估只读导入或重建；非托管外部连接默认只解除绑定，转企业托管须核实语料归属和移交，不静默删除用户远端数据。具体契约以 [06](06-postgresql-native-store-plan.md) 为准。

**A2 验收**：目标存储契约与每个调用链同时通过；无任意对象 key、越权下载、超额上传、孤立 metadata 或仅在原 Pod 能读的产物。

### A3：单租户生产验收

**部署工作从 A1 起并行启动，A3 是最终集成验收，不是第一次接触 Kubernetes。** 提前开发 Woodpecker 流水线，准备生产镜像/清单、测试 namespace、PG/HugeGraph/S3、Secret、Service/Ingress/TLS/WS 和 probes，将 A1/A2 的增量功能持续放到同构环境验证。

流水线按“接入契约 → 质量检查与生产镜像适配 → 不可变制品 → 测试环境迁移/部署/smoke → 受控生产晋级与回退”细化，分别有真实验证；完整方案见 [05](05-woodpecker-kubernetes-pipeline.md)。源仓库已有 GitHub Actions，但当前没有 Woodpecker 配置；现 Docker 入口的本地 JSON 配置与前后端合并启动需适配，不能只新增部署 YAML。

A3 汇总首发功能回归、所选运行模式验证、故障/备份恢复、存量切换及发布证据。示例配置是不可直接执行的拟新增契约，首发 provider 已确定为 `lightrag-server`，不代表当前 repo 已实现：

```bash
DEEPTUTOR_DEPLOYMENT_MODE=single_tenant
DEEPTUTOR_DEFAULT_TENANT_ID=<稳定内部 UUID>
DEEPTUTOR_STORAGE_BACKEND=postgres
DEEPTUTOR_OBJECT_STORE=s3
DEEPTUTOR_RAG_PROVIDER=lightrag-server
DEEPTUTOR_RAG_GATEWAY_URL=<internal-service-url>
AUTH_ENABLED=true
```

M1 不等待 EduPlus2 接入或新运营界面；现有单租户管理功能通过企业目标 `/tms` 与 `/api/v1/tms/*` 专属接口继续可用，仍限固定内部租户和已有管理能力，不提前开放平台运营；平台 Secret 不可被页面/API 导出。

### G1：M1 发布门禁

G1 区分**发布前放行**和**发布后完成确认**：先在同构测试环境完成 A1/A2、故障/恢复/安全及适用 G-H，检查生产配置并取得批准；再受控部署生产、执行隔离 smoke 并归档证据，最后确认 M1 上线。不能要求“先有生产成功记录才允许首次部署”，也不能因已经部署就跳过后验或提前开放普通业务流量。

| 验证 | 通过标准 |
| --- | --- |
| Woodpecker 自动交付 | 目标 agent 实跑检查/构建/推送/迁移/部署/HTTP+WS 业务 smoke，同 digest 经批准晋级生产；证据可追溯 |
| 流水线安全与故障 | 非可信来源/未批准/环境错误拒绝；迁移失败阻断，发布互斥/旧构建/中断恢复/兼容回退演练通过，无 Secret 泄露 |
| 首发功能清单 | 登录、聊天、历史、KB/RAG、附件、memory/notebook、产物、`/tms` 管理设置和已启用能力均完成真实替换，菜单/深链接/专属 API 前缀一致 |
| 重建 Pod/清空 scratch | 账号、配置、历史、KB、文件可恢复；不依赖原 Pod 本地状态 |
| PG/HugeGraph/S3/必要 RAG 服务失败 | 就绪检查或相应操作明确失败；不写 SQLite/local fallback，不切换默认检索 workspace，不返回未持久化/未索引成功 |
| 企业扩展与调用覆盖 | 企业启动器实际安装身份/Store/RAG providers；缺 seam/版本不符拒绝启动，所有已启用 API/tool/worker 无旧写旁路 |
| LightRAG 上线验收与完整链路 | 包含 HugeGraphStorage 的固定 fork 制品/HugeGraph 版本/schema/权限/实际解析及必要队列拓扑、真实质量及预算证据；低权启动、授权/数据库防线、导入→ready→图检索→授权源文→删除/重建；清空 scratch 可恢复，缺证据不得因选型已确定发布 |
| 多租户底座前置验收 | M1 虽只开放一个生产租户，A2/G1 已用两个测试租户及同租户两个普通用户验证 PG/图/S3/缓存/job 隔离、私有 KB、同名实体、跨库图遍历、撤权和引用；受限身份直接 REST/Gremlin 越权也被拒绝 |
| 并发/重复请求 | 事件顺序、唯一约束、对象预留/核算与幂等正确；同 scope 独立写部署拒绝，写超时/取消/部分提交与 pending fence 恢复通过，不靠重启或换 URI 绕过 |
| 对象故障与安全 | pending/孤立对象/删除重试可修复；任意 key、超额、过期 URL、他人资源拒绝 |
| 认证及 Secret | 未认证 401，越权 403/404，管理员也不能导出平台明文凭证 |
| 运行模式 | 单执行模式通过排空/在途失败/重连/容量验证；要求高可用或启用多执行者则必须先通过 G-H |
| 成套恢复与切换 | 应用/检索 PG、HugeGraph 数据/schema/权限及 S3/binding 引用一致；记录实测 RPO/RTO，旧写入关闭，回退兼容范围明确 |

## M2：多租户及各租户管理界面

### B1：EduPlus2 单租户闭环

**外部准备提前，生产开放分步。** 在 A1/A2 期间就协调 EduPlus2 app 注册、测试租户/账号、redirect、Handoff/OIDC、权限、client 校验接口和 Webhook 契约；不要求 M1 完成登录集成，也不把准备活动做成独立过渡项目。首个指定租户接入可先不接入 Webhook，但必须使用实时 JWT/client 校验、短期缓存和受控同步完成安全闭环。

以 M1 的一个固定内部租户为验证对象，交付最终实现：

- 签名/claims/code/state 校验、身份映射、`/me/profile`、具体操作权限与会话生命周期；DeepTutor 不提供普通用户注册。
- 显式绑定原内部 tenant/user 到外部 tid/eui，幂等可回退；不按同名合并账号，不搬 PG/S3。
- HTTP/WS/后台任务可信上下文、权限依赖失败拒绝、用户/租户停用及撤权传播；TMS/OMS 是唯一需要 DeepTutor 交互式登录的入口。
- 首租户所需状态校验、受控同步与权限缓存失效路径；如启用 Webhook，必须签名校验且 PG 持久化接收后才确认。Webhook 不是每次登录或第三方 token exchange 的主链路，不能把安全依赖留到 B2。
- 用首租户真实账号完成“工作台进入→聊天→KB/附件访问→重新登录/撤权”验证，并完成一个第三方应用传入 EduPlus2 user JWT 后静默换取 `dt_token` 的调用链。

**B1 验收边界**：TMS 先只管理一个指定租户；其他未绑定租户仍被拒绝；学校管理员不映射全局 admin。使用最终 adapter，不另建临时 token 透传或认证网关。可受控发布单租户接入版本，但它不代表完成 M2，也不要求已完成全部租户管理 UI。

### B2：多租户与租户自管理

B1 接入闭环通过后，使用同一底座逐项交付：

- 租户初始化/失败重试，暂停和恢复各有幂等状态机、权限与审计。
- 平台给租户分配模型/功能范围；租户 grants 不越过平台或外部权限上限。
- 用量记录、token 额度与并发预留/释放分项验收；额度在真实 agent/tool 与受管索引任务生效，远端检索/embedding/导入用量单独记录，不默认包含在聊天 cost_summary。
- PG/RLS/连接池、owner/grant、S3、向量/图检索、cache/job、SDK/M2M 全链路租户隔离。
- 必要组织关系缓存、周期对账、多租户 Webhook 幂等/重试/撤权；不重建全部 EduPlus2 主数据平台。
- 复用现有管理界面，在 `/tms` 微调租户标识、KB、用户授权、设置/模型选择、EduPlus2 client/app 注册及菜单/路由/按钮权限，专属管理接口使用 `/api/v1/tms/*`；不复制每租户前端或 Deployment。

B2 使用 `/api/v1/oms/*` 承载跨租户只读治理 API；开放前先完成可信平台身份/具体能力/目标租户绑定及默认运维授权，相关默认数据走版本化迁移并验证无权限拒绝；C1 复用运营角色和界面，不是首次补鉴权。**非计费租户生命周期**开停/恢复以 EduPlus2 签名 webhook 为权威，DeepTutor 在全入口执行其准入；欠费另用独立模型资格事件，只在实际模型调用前执行。授权、配额和 client/app 写操作仍由各自获授权的 DeepTutor/TMS/EduPlus2 流程承担，**不在 OMS 提供写入口**。治理与安全后端不等待 C1，统一运营界面不反向阻塞 M2。

### G2：M2 发布门禁

- B1 首租户接入通过；集成环境新增第二租户及各自管理员/普通用户，全量正负向验证后才开放多租户生产流量。
- 相同外部 eui、KB 名称、猜测 session/object ID、伪造 scope 均不串租；已有首租户数据和对象 key 不变。
- 所有入口、数据库连接池、检索、缓存、对象下载与后台任务均验证租户/用户边界；所选 RAG 相同 KB 名称、错误 binding/调用凭证/远端 tenant/KB/workspace、个人私有 KB 越权、跨语料图污染与数据库跨 namespace 读写均有拒绝负例，不能先跨租户检索再过滤。
- tenant_admin 默认通过 `/tms` 管理本租户；自定义权限角色正例及无权限 403/隐藏菜单负例通过，导航/深链接/`/api/v1/tms/*` 一致，无平台 Secret/跨租户管理入口；直接请求 `/api/v1/oms/*` 仍拒绝，不因 URL 改名自动授予 `tenant.*` / `ops.*` 能力。TMS 注册当前 tenant client 成功、其他 tenant client 被拒绝；OMS 仅按授权查询已归口 client。
- 开停/撤权影响旧 token、WS、新 turn、下载授权与任务派发；短时 URL 的撤权时效明确；`dt_token` 支持 WS 静默刷新，已接受 turn 不因 token 自然到期中断，新 turn 必须重校验。
- 模型策略、token/并发额度和失败释放真实生效，统计/审计可解释，不只是 UI 显示限制；审计包含 client/app/tenant/user/session/turn 关键字段且不记录 token/secret/完整私密正文。
- **不要求因“第二个租户”就启用第二个 Pod。** 可接受单执行模式时记录容量与维护窗口；多副本或 HA 为发布目标时，G-H 成为本次 G2 的前置，不允许绕过。

## M3：统一运营管理后台

### C1：运营管理闭环

前置是 M2 已交付。复用 B2 服务，实现平台角色与 `/oms` 入口、跨租户只读 API、全租户目录/详情、EduPlus2 权威 lifecycle 状态、client/provider/策略/任务/审计只读视图及普通运营文案。Provider 全服务维护另由 DeepTutor 平台设置交付，OMS 不承担租户开停、Secret/策略/角色/任务写入。

**G3a 工作包门禁**：平台只读 API 与页面按具体权限一致，状态来自真实权威源；operator/auditor 无越权能力，tenant_admin 不能进入运营 API，租户管理界面继续可用。C1 可单独发布为运营基础能力，但不能声称 M3 全部完成。

### C2：运营治理完善

基于逐调用供应商真实 usage 总账，逐项完善租户→用户→调用 Token 明细、版本化每百万 Token 单价及 Decimal 费用、仅 OMS 可见的供应商成本拆分、欠费**模型资格**处理请求与 EduPlus2 独立 webhook 生效确认，并补足存储/错误/同步/Webhook/导入/turn 状态及只读审计筛选/导出。限制生效后仅拒新模型调用，登录、TMS/OMS 管理、历史查询及非模型操作继续可用。无可信 usage 不收费，任务重试/取消仍归原业务/运维入口。

C2 的查询开发可在 C1 契约稳定后并行，最终验收依赖 C1 角色和入口；不能在没有权限约束的临时后台演示。**C2 保留在本次完整范围，不因 C1 可发布而省略。** 两级管理边界见 [12](12-platform-operations-admin.md)。

### G3：M3 完整发布门禁

- C1/G3a 与 C2 全部完成；覆盖完整 [12 权限矩阵](12-platform-operations-admin.md)。
- admin/operator/auditor、tenant_admin、普通用户及自定义授权角色的入口/API 正负向一致。
- EduPlus2 非计费租户 lifecycle webhook 的全入口准入、独立欠费模型资格 webhook 的逐模型调用限制、计费版本/Decimal 精度、重复提交及审计符合实际状态；欠费时登录/管理/历史/非模型操作正例通过，OMS 不执行 provider/Secret/任务写操作。
- 聚合统计不默认读取私有对话/附件；导出单独授权，Secret 不回传明文，无任意 tenant override 或超级连接旁路。
- 逐调用真实 Token 用量、待核算、成本隔离、失败处理、日志/审计脱敏及此前 M1/M2 功能回归通过；本次运行模式要求的 G-H 证据仍有效。

## 独立工作线 H：可用性、容量与多副本

H 不与 M2 绑定。A1 开始记录目标并选择运行模式，每次正式发布重新评估；本方案不凭空指定 SLA 或压测阈值，实际目标必须进入发布记录并取得业务/运维确认。

| 运行模式 | 适用条件 | 必须满足 |
| --- | --- | --- |
| 单执行模式 | 容量足够，明确接受非 HA、维护窗口与故障中断 | 限制并发执行者，排空/恢复/超时清理/配额仍正确；业务与运维确认并留证据 |
| 多执行者/高可用模式 | 首发或任意后续发布的容量/可用性要求触发，或实际启用多 Pod/多 worker 竞争执行 | 先实现协调并通过 G-H；不能仅改 replicas、加 sticky session 或依赖 PG/S3 自动恢复 |

**G-H 在启用多执行者前强制通过**：

1. durable turn/job/command、原子领取、owner lease/fencing，旧执行者失效后不能继续提交。
2. 请求落任意 Pod 的订阅、事件游标重放、cancel/reply、重复命令幂等和权限一致。
3. 执行者故障、网络中断、滚动更新与扩缩容下状态可解释，不遗留无限 running 或重复核算。
4. 对象额度、token/并发预留及释放在适用发布功能范围内一致，故障重试不重复产生已完成副作用。
5. 检查 PG/HugeGraph/S3、Ingress/连接路由、队列（如有）等依赖故障与恢复目标；两个 backend Pod 本身不等于端到端 HA。
6. 压测及故障演练满足本次已确认目标，记录允许中断/恢复语义，不承诺未实现的 agent 自动续跑。

单执行模式只验证当期能力并记录 G-H 未触发及扩容前置任务；**不把未做的多副本任务勾为完成**。H 目标评估、基本监控/恢复、安全与 upstream 回归无论何种模式都不能跳过。

## 任务粒度与完成标准

七个工作包在 OpenSpec 中各有一个任务组，H 单列条件性任务组，不是第八次上线。原大项拆成可审查的行为，例如“租户暂停”和“租户恢复”“并发预留”和“用量核算”“附件下载授权”和“对象补偿”，避免一个 checkbox 包含数个独立子系统。

每项任务完成需满足：

1. 适用数据迁移/约束和旧数据处理已交付，未涉及说明理由。
2. 接入真实 UI/API/agent/worker 调用；基础设施任务用实际命令/部署路径验收。
3. 权限、校验、并发、幂等、失败恢复等适用要求有实现和负向证据。
4. 存储替换后原生产写路径退出，不能用 stub/mock 演示代替目标依赖集成测试。
5. 有清晰依赖、验收记录及切换/回退说明；未完成部分不能靠在文档中描述来勾选。

任务以可独立审查的 PR/变更为单位；文件数量少不是目标。存在多个独立用户行为或无法解释完成证据时继续拆分；不要按“先所有 SQL、再所有后端、最后所有 UI”的水平层切割。

## 数据切换：一次迁入，不建设双写

### 无存量数据

第一阶段直接初始化应用/检索 PG、受控 HugeGraph 资源/schema/权限及 S3/binding；不要为不存在的旧数据开发通用迁移平台。第二阶段只扩展租户映射及必要字段，第三阶段不换存储。

### 确有存量需要保留

1. 明确资源所有者与目标内部 tenant/user，旧全局 admin 数据不自动公开给租户。
2. 一次性导入工具提供 dry-run、源只读、备份、资源数量/校验和/引用完整性验证、幂等断点与迁移审计。
3. 在维护窗口停止旧写入，导入业务 PG/S3，并按 06 在新 index-version 重建匹配的检索 PG/HugeGraph、验证后切 binding；启用目标系统写入后旧库只读归档，不回写同步。
4. 导入前失败可继续原系统；目标系统产生新写入后，不允许简单切回旧 SQLite 丢弃新数据。使用兼容当前 schema 的应用回滚，或停止写入后按批准的应用/检索 PG、HugeGraph 数据/schema/权限及 S3/binding 成套备份恢复流程处理并明确数据损失窗口。

迁移 SQL/默认角色/历史映射走版本化迁移，不在每个 Pod 启动时无版本修补数据。EduPlus2 的 OpenFGA/Keycloak 变更由其受控 provider migration 执行；本仓库不直接改外部运行态。本次只更新文档，未新增或执行实际迁移。

## 发布与官方更新

M1 建成的 Woodpecker 流水线在 B1/B2/C1/C2 和官方更新中复用：构建一次、按 digest 晋级，测试与生产凭证隔离；迁移、部署、业务 smoke 和回退共用环境锁，不通过手工直改集群绕过门禁。每次发布必须验证同版本/拓扑适用的门禁证据，缺失或失败不得放行。

每里程碑发布记录流水线 ID/批准人/目标环境/制品清单与工作包状态、运行模式/容量及可用性目标、upstream SHA、自有 SHA、镜像 digest、schema/对象格式、启用能力、验证证据、已知限制和回滚兼容范围。后续合并官方更新必须重跑当时已发布的 G1/G2/G3 及适用的 G-H，不把官方 SQLite/file 新路径重新带回生产。

## 文档读者核对问题

1. 是否从三个阶段变成七套系统/七次生产上线？不是，三个业务里程碑下有七个集成验收工作包。
2. 是否等 A1/A2 完成才准备 K8s？不是，部署和外部契约准备从 A1 并行，A3 才是完整生产验收。
3. B1 是临时认证方案吗？不是，在一个真实租户验证最终实现，B2 扩大租户集合。
4. 租户界面与运营界面何时交付？M1 `/tms` 保留固定租户既有管理功能；B2 完成多租户 TMS 和 OMS 治理 API；C1/C2 交付 `/oms` 运营界面并保留 `/tms`，完整命名见 [11](11-api-and-entrypoints.md)。
5. 多租户是否强制两个 Pod？不因租户数量强制；运行目标决定是否触发 G-H，多执行者未验收不得开启。
6. C1 可发布是否表示省略 C2？不是，M3 必须完成 C1+C2。
7. 无时间做过渡是否可以跳过验收或静默删功能？不可以；只调整研发粒度，不减小已确认完整范围。
8. Woodpecker 是否另增一个阶段？不是，A3 内细化开发子环节，从 A1 并行，G1 前必须真实交付，后续复用。
9. 是否已经实施？整体路线尚未交付；用户批准的首个 A1 身份/PG 会话子切片已有工作区实现与隔离验证，[执行证据](../../openspec/changes/add-enterprise-pg-identity-session-slice/execution-evidence.md) 单独记录。S3/LightRAG/流水线等未实施，完整 A1/G1 仍未通过，也未创建或触发生产流水线。
10. 是全产品零改源码吗？不是；优先配置/现有扩展点，必要通用核心改动与真实调用收敛仍需完成，不用厚壳或运行时 monkey patch 伪装低维护。
11. 多租户能否到 B2 再设计？不能；M1 建 namespace、owner/grant、PG/图/S3 强制防线与双租户负例，M2 只是外部身份和真实多租户放量。
12. fork 有 HugeGraphStorage 是否算已投产？不算；固定包含实现的制品及低权权限、真实图质量、容量和跨存储恢复均须重验，旧 PG 图测试不覆盖新组合。
13. LightRAG 已选定是否表示不用做 A2？不是；当前 adapter 是检索连接，A2 仍需交付完整托管文档、PG、S3 原文与派生物、图检索、引用、删除、权限和恢复，并通过生产验收。
