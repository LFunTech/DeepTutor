# POST `/api/v1/resources/upload-intents/{resource_id}/complete`

## 用途与时机

预签名 PUT 成功后调用，取得可在 `start_turn.resource_ids` 中引用的稳定资源 ID。

## 前置条件

有效 `dt_token`；必须先有当前用户的上传意向并成功上传对应字节。

## 请求

**POST `/api/v1/resources/upload-intents/{resource_id}/complete`**

| 参数 | 必填／默认 | 说明 |
| --- | --- | --- |
| `resource_id`（path） | 必填 | 创建意向响应中的 ID |
| `resource_kind`（JSON） | `turn_input` | 1～64 字符；对话输入使用默认值 |

```bash
curl --fail-with-body -X POST "$BASE_URL/api/v1/resources/upload-intents/$RESOURCE_ID/complete" \
  -H "Authorization: Bearer $DT_TOKEN" -H "Content-Type: application/json" \
  --data '{}'
```

## 响应

`200` JSON：`resource_id`、`object_id`、`resource_kind`、`state`、`size_bytes`、`sha256`、`mime_type`。只有成功完成后才把 `resource_id` 放入 `start_turn.resource_ids`。

## 错误与恢复

`404` 意向不存在／不可见；`409` 上传对象与声明不符或状态不允许完成；`403` 无权限；`503` 暂不可用。先核对 PUT 是否完成，不要猜新的资源 ID。

返回 [HTTP API 目录](../../http-api.mdx)；通用鉴权和状态处理见 [认证与安全](../../auth-and-security.mdx) 与 [错误与排障](../../errors.mdx)。
