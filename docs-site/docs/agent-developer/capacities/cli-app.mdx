# CLI 工具集成开发规范

CLI 应用是一个有固定可执行入口、通过参数数组运行的命令行程序。它不同于只提供指导的 [Skill](skill.mdx)、模型按 schema 调用的普通 [Tool](tool.mdx)，也不是给 Agent 任意 shell 权限。当前 DeepTutor **只识别预置目录中有条目的应用**；不存在任意第三方 CLI 包放入目录就自动成为工具的通用插件加载器。

## 企业入口适用状态

当前企业第三方 API 不开放 CLI 应用目录、登记、安装或执行接口。`start_turn.tools`、`mcp_tools` 以及顶层 `capability` 均不能作为 CLI 应用选择器。本页是目标自部署版本的交付与运行契约，不是企业调用保证。

## 交付物与格式

交付可复现的 Python/npm 包、单一可执行入口及面向 Agent 的命令说明。当前自部署目录条目需要以下数据；这张表用于**核对目标版本目录能否表达你的应用**，不是一个开放提交格式：

| 条目字段 | 当前规则 |
| --- | --- |
| `id` | 必填，匹配 `^[a-z0-9][a-z0-9._-]{0,63}$`，总长 1～64；也是工具名 `cli_<id>` 的后缀。 |
| `display_name`、`description` | 必填且去空格后非空；说明用途、输入和副作用。 |
| `category`、`origin` | 目录分类与来源；`origin` 为 `harness` 或 `public`。 |
| `entry_point` | 可安装应用必填，匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`；只能是入口文件名，不得含路径分隔符或以点开头。 |
| `install` | 必须能解析为当前支持的单包计划，或标记 `unsupported` 并给出原因；不直接执行来源资料里的安装命令。 |
| `version`、`requires`、`homepage`、`source_url`、`doc_ref`、`install_notes` | 可选说明信息；使用说明应随实际包可读取，不应依赖运行时抓取网页。 |

当前可执行安装计划只识别固定版本的 harness、单个 Git/Python 包或单个 npm 包；复合命令、多包安装、`curl | sh`、重定向、管道和任意 shell 脚本不能作为可安装计划。预置目录不包含你的应用时，交付合规包**仍不会自动增加一个 `cli_<id>` 工具**；需要目标部署版本先具备相应目录条目。不要把此约束写成第三方自助登记流程。

面向 Agent 的说明应列出真实子命令、每项参数的类型/取值、输入文件与输出格式、退出码、副作用、重复运行与覆盖策略。说明文本是参考数据，不是给智能体新增权限的指令。

## 输入与输出

应用以 `cli_<id>` 的延迟加载 Tool 形式供受权的聊天轮次使用，参数契约为：

| Tool 参数 | 当前规则 |
| --- | --- |
| `args` | **必填 `string[]`**，一个数组元素对应一个 argv 参数。不得写成整段 shell 命令；引号、管道、重定向不会得到 shell 解释。当前执行器容忍字符串输入并按空白拆分，但这是兼容处理，不是建议格式。 |
| `timeout_s` | 可选整数，默认 120 秒；上限 600 秒。传 `0` 或缺省会使用 120 秒，负数钳制为 1 秒，超过 600 秒钳制为 600 秒；无法转换为整数时回退 120 秒。 |

固定可执行入口与参数向量一同送入受控执行环境；工作目录、挂载和环境范围由运行环境决定，**不是模型在 `args` 中自行授权**。输出给模型的文本最多 **20,000 字符**；运行结果还记录应用 ID、参数、`exit_code`、`timed_out`、执行环境错误及新产物信息。标准输出/错误信息应可读、稳定且脱敏；需要生成文件时说明名称、覆盖与幂等规则，不要只输出本地私有路径。

应用是否能被提供还取决于：目标目录条目存在、应用已安装、当前账户获授予该应用、未被该账户禁用、代码执行被允许且执行环境可用。通讯代理不因拥有者获授权而自动获得其 CLI 应用。**已安装不等于任何用户都可执行**。

## 安全与资源边界

不读取宿主密钥或未授予的目录，不假设可访问任意网络。将参数、输入文件和命令说明均视为不可信数据，对路径遍历、恶意文件和超大输入做限制。高影响子命令应设计显式确认和可重试的幂等标识；命令说明不能替代服务端授权。调用外部程序时不要借子进程绕过当前工作目录和执行范围。

## 失败处理

区分**应用退出**与**Tool 执行故障**：应用返回非零 `exit_code`，当前适配器仍把它当作给模型阅读的应用结果，`ToolResult.success` 通常仍为 `true`；只有执行环境本身报告错误时才置为 `false`。因此应用应使用非零退出码和清楚的错误文本描述参数错误、输入缺失、无权限及业务失败，不能指望 DeepTutor 自动把每个非零码提升为 turn 级失败。执行超时会在运行结果中标记 `timed_out`；调用方应据 `exit_code`、`timed_out` 和错误信息判断是否重试，避免对已有副作用盲目重跑。

目录中不支持的安装计划、缺失入口或目录条目、授权不足、执行环境不可用时，不应宣称应用已经执行。失败也不应留下看似完整的输出文件。

## 可验证样例

如果目标版本已收录 `course-report`，模型调用该工具时应传**参数数组**，而非拼接一条命令：

```json
{"args":["summarize","--input","lesson.txt","--format","json"],"timeout_s":120}
```

这对应固定入口后面的 `summarize --input lesson.txt --format json`。成功可输出稳定 JSON 并以退出码 `0` 结束；输入缺失时输出脱敏错误、返回非零退出码。**示例 ID 不代表当前预置目录已经收录该应用**，也不是企业安装或调用请求。

## 开发自测

- 核对目标版本是否确有目录条目，ID/入口名、单包安装计划、运行时依赖与使用说明均真实匹配。
- `args` 逐项传递；带空格、引号、管道字符的参数不会变成 shell 指令。
- 验证 120/600 秒边界、长输出截断、新产物和重复运行/覆盖行为。
- 分别模拟非零应用退出、执行环境错误、超时和无权限，检查 `exit_code`、`timed_out`、`ToolResult.success` 的真实区别。
- 未获目标环境明确支持前，不把 CLI 应用列为企业 Agent 可执行 Capacity。
