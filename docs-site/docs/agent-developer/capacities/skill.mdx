# Skill 规范

Skill 是面向智能体的任务说明与参考材料，不是可执行 Tool，也不是模型权限声明。适合把学校的教学方法、答题步骤或内容风格写成可复用指导；若需调用外部系统，应另设计 [MCP](mcp.mdx) 或 [Tool](tool.mdx)。

## 企业入口适用状态

当前企业 `start_turn.skills` 可以选择**当前用户已获授权且部署方提供的真实 Skill ID**；这不意味着第三方可以经公开 API 上传 Skill。`skills` 选择只表示本轮请求，实际是否使用请查看 `done.metadata.capability_usage`；详见[对话能力选择](../capability-selection.mdx)。本页不描述交付后的发布操作。

## 交付物与格式

当前交付结构为一个独立目录，根部必须有 `SKILL.md`，可附 `references/` 等支持文件。文件以 YAML frontmatter 开始，正文给出适用条件、任务步骤、停止条件与输出验收要求。当前 DeepTutor 以**目录名**作为运行时 Skill 名称；frontmatter 的 `name` 应与其一致，包导入时会按最终名称改写。可参考 [Agent Skills 规范](https://agentskills.io/specification)，但实际可用字段以此页的 DeepTutor 子集为准。

## 当前实现的元数据契约

| 字段 | 已实现规则 |
| --- | --- |
| `name` | 应与目录/Skill ID 一致；当前本地名称按 `^[a-z0-9][a-z0-9-]{0,63}$` 校验（最多 64 字符），规范化为小写。名称不授予任何权限。 |
| `description` | 说明**什么时候使用**，并能区分其他 Skill。包导入要求最终有非空描述：优先使用文件中的此字段，目标导入入口若显式提供备用描述也可使用；独立交付时应在文件内填写。普通自编 Skill 的摘要也取自此字段。 |
| `tags` | 可选列表，仅用于分类；每个标签最长 32 字符，首字符为小写字母或数字，其余可含小写字母、数字、空格、`-`、`_`。 |
| `always` | 对当前自编/内置 Skill，`true` 表示可用时把正文直接加入本轮上下文；普通 Skill 则先显示名称/描述，再由模型按需读取。**外部导入的包会去掉 `always`**，不能靠它强制常驻。 |
| `requires.bins`、`requires.env`、`requires.sandbox` | 可选可用性门槛，分别检查所需命令、环境变量和执行环境；任一缺失则标记不可用。这些字段只表示依赖，不会自动安装软件、注入凭证或授予执行权限。 |
| 其他 frontmatter 字段 | 导入包可保留未知字段，但当前运行时不会因此获得新功能；不要把标准文档中的可选字段当成已支持的权限机制。 |

外部包若使用 Agent Skills 风格的顶层 `bins`、`env`，当前导入路径会把它们合并到 `requires.bins`、`requires.env`；后续可用性判断仍只按 `requires` 执行。`requires.sandbox: true` 按 shell 执行环境检查，字符串值按对应执行环境类型检查。缺少依赖只使 Skill 不可用，不会自动下载命令或提升权限。

## 当前实现的包与读取限制

- 包根必须有 `SKILL.md`；单文件不超过 **1,000,000 字节**。当前导入路径最多接受 **500 个支持文件**、支持文件合计 **20,000,000 字节**，单个支持文件也不得超过 1,000,000 字节。
- 支持文件只接受文本/脚本类扩展名：无后缀、`.md`、`.markdown`、`.txt`、`.rst`、`.py`、`.js`、`.mjs`、`.ts`、`.sh`、`.rb`、`.lua`、`.r`、`.json`、`.jsonl`、`.yaml`、`.yml`、`.toml`、`.ini`、`.cfg`、`.csv`、`.tsv`、`.html`、`.htm`、`.css`、`.xml`、`.sql`、`.jinja`、`.j2`、`.tmpl`、`.template`。不支持的后缀和超大支持文件会被跳过；符号链接会使导入失败；隐藏文件/目录会被忽略。
- 智能体按相对路径读取支持文件；绝对路径、`..` 路径和越过包目录的路径被拒绝。单次读取超过 **100,000 字符**会截断并加标记，因此应把长资料拆分到可定位文件。
- 支持文件中的脚本**不会因 Skill 被选择而自动执行**。需要执行时，还必须存在独立受权的工具与执行环境。

## 输入与输出

Skill 的“输入”是用户任务及被授权的上下文；“输出”是对智能体行为的指导，不直接返回 API 响应。把需要的先决资料、缺资料时的处理、引用要求和最终答复格式写清楚。当前可见 Skill 会以名称/描述呈现给模型；按需读取与显式选择可能使正文进入本轮上下文，**但这仍不保证模型照做或实际调用了配套工具**。以 `done.metadata.capability_usage` 判断请求项状态，不把“已选择”当成“已使用”。

## 安全与资源边界

Skill 不得包含真实密钥、系统提示词绕过指令或跨学校共享的敏感内容。引用资料仅限目标用户有权访问的范围；对外部文本中的对抗性指令作隔离。若附脚本，需明确运行前提和副作用，不应因 Skill 被选中就默认可执行。

## 失败处理

缺少参考资料、前置工具或用户授权时，应让 Agent 说明无法完成的部分，不能编造引用。目标部署不支持某个 frontmatter 字段或附件时，应去除依赖或改写规范；不要把“Skill 已选择”显示为“已使用”。

## 可验证样例

```md
---
name: explain-concept
description: 在学生请求解释课程概念时，先给直观说明，再给可核查的例题。
---

# 解释课程概念

1. 确认学生的问题及课程范围；缺少范围时先澄清。
2. 用简短语言解释核心概念，并给一个可验算的例题。
3. 只有实际读取受权资料后才列引用；不确定时明确说明。
```

这里的 `name` 只是交付物标识，不能代替部署方提供的受权 `skills` ID。

## 开发自测

- frontmatter 可解析，`name` 与目录/交付约定一致，`description` 能准确触发。
- 用真实包结构验证支持文件后缀、大小、数量、符号链接与相对路径读取；确认长文件截断行为。
- 分别验证普通、`always: true`、外部导入及 `requires` 不满足时的行为，不把依赖检查误写为权限。
- 无参考资料、无工具、无授权和冲突指令时能安全降级。
- 引用只来自已读取材料；没有把 Skill 文本当作新的权限。
- 在可用环境中检查“请求、启用、实际使用”显示差异。
